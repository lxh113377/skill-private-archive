# 06-constraints.part10 -- 纪律条目正文归档（#30-#48，r154 从 AGENTS.md 迁入，原文零改写）

## ⚠️ 归因须到人与次（#39，2026-10-21 立规）

#38（漂移须可归因）立了之后，r140 收尾发现归因还差一环：印记只记「模板 sha + 安装时间」，
**回答不了「谁装的、为什么装」**。多会话 / 多人装 hook 时，仍无法归因到具体那次安装。

**解法 = 印记加 invoker 与 reason 两字段**（`r138_install_hooks.py` 写入）：

| 字段 | 内容 | 取不到时 |
|---|---|---|
| `invoker.git_user` | `git config user.name` | 留空 |
| `invoker.git_email` | `git config user.email` | 留空 |
| `invoker.session` | `DSH_SESSION_ID` / `CLAUDE_SESSION_ID` / `TERM_SESSION_ID` | 留空 |
| `invoker.pid` | 进程 pid | 必有 |
| `reason` | 环境变量 `HOOK_INSTALL_REASON` | 记为「(未说明)」 |

**原则：全部自动取，取不到留空并显式说明，禁猜、禁硬编码。**

**机器判据**：第 53 门（`r141_hook_attribution.py`）四项断言 ——
A1 印记存在 / A2 有 `git_user` / A3 有 `session`（**多会话归因的关键**）/ A4 有 `reason`。
任一不通判红；`reason` 为「(未说明)」不判红但单列告警。

**分工（与第 52 门）**：第 52 门答「**哪次安装、怎么漂移的**」（六态），
第 53 门答「**谁、为什么装**」（invoker + reason）。两者互补，不重叠。

**反向验证（r141 实测，三态）**：

| 变体 | 读数 | 判定 |
|---|---|---|
| 旧印记（无 invoker/reason） | `a2` / `a3` / `a4` 精准 FAIL | 有牙 |
| 完全无印记 | `a1` ~ `a4` 全 FAIL | 有牙 |
| 真实状态 | 0 项 FAIL | 不冤枉 |

## ⚠️ 归因须可回溯（#40，2026-10-21 立规）

#39（归因须到人与次）立了之后，r141 收尾发现归因链还差最后一环：`.installed` 是**快照**，
每装一次就被覆盖 —— **只能归因到最近一次安装，更早的记录彻底丢失**。

**r142 量化坐实**：连续装两次（reason 分别为 A、B），装完在第 2 次后于整套 `.git/hooks/`
内搜 reason=A —— **搜不到**。快照只有 B，A 无处可查。

**解法 = 快照 + 追加式历史**（`r138_install_hooks.py` 每次安装写两处）：
- `.installed` 快照保留（兼容第 52/53 门的现有读数面，schema 不变）；
- `.installed.log` **追加一行 JSONL**（含 `seq` 单调序号），永不覆盖。

**机器判据**：第 54 门（`r142_install_history.py`）五项断言 ——
H1 历史存在非空 / H2 每行 `seq`+`installed_at`+`invoker`+`reason` 四要素齐 /
H3 `seq` 严格单调增 / H4 末行与快照一致（同一次安装写两处，不许只写一处）/
H5 至少 2 条（**证明追加真的在发生**——只装过一次时历史与快照等价，看不出追加是否工作）。

**反向验证（r142 实测，四态）**：

| 变体 | FAIL 项 | 判定 |
|---|---|---|
| 历史被删 | 5 项全红（H1-H5） | 有牙 |
| 只剩 1 条 | **H5 精准** | 有牙 |
| `seq` 乱序 | **H3 + H4** 精准 | 有牙 |
| 坏 JSON 行 | **H2 + H4** 精准 | 有牙 |

**归因链四层全景**：健在性（第 50 门，防丢失）→ 一致性（第 51 门，防漂移）→
哪次+怎么漂移（第 52 门）→ 谁/为什么装（第 53 门）→ **每次安装的完整历史**（第 54 门，防覆盖）。
