## ⚠️ 跨会话宽限须留安装凭证（#44，2026-10-21 立规）

#43（锚点对账须容窗口期）立了之后，r145 收尾发现宽限的信任面只够到**单会话**：
三条件判别依赖「缺行 session ∈ 当前进程 env 会话」。但**会话 A 装、会话 B 跑门**时，
B 的 env 里没有 A 的 session ⇒ 三条件失效 ⇒ 误红。r146 量化坐实：跨人跨会话窗口期
（末行 git_user/session 属他人 + 台账落后 1 行）⇒ H7 误红（`_temp/v30_probe.py`）。

**难点**：env 会话标识只反映**当前进程**，无法回答「这一行历史上是谁装的」。

**解法 = 安装即写 git 内 pending 凭证件**（`hook_install_pending.json`）：
安装时同步把「已装未提交」行的 `line_hash` + `lines` + `invoker` + `reason` 写进
**git 可跟踪**的 pending 件。对账时（H7 第四宽限路径）：
`pending.line_hash == 实际末行` 且 `pending.lines == 实际行数` 且 `台账 lines == 实际-1`
且 `台账 last_line_hash == 倒数第二行` ⇒ 缺行系「已装未提交」的合法新增 ⇒ 宽限（显形，不静默）。

**机器判据**（H7 pending 通道，四态反向验证 r146）：

| 变体 | 读数 | 判定 |
|---|---|---|
| 跨人 + pending 有效凭证 | h7=True，走 pending 通道宽限 | 容对 |
| 跨人 + pending 过期（line_hash 对不上） | **判红** | 无凭证不放过 |
| 真截断（台账 lines > 实际行数，missing<0） | **判红** | 宽限不放过截断 |
| 真实状态 | h7=True | 不冤枉 |

> 复现：`python ./_temp/v30_verify2.py`（四变体逐一跑，跑完即还原现场）。

**信任强度（诚实声明）**：伪造 pending 需改 git 跟踪的工作区件 ⇒ 与伪造台账同强度
（改它必留 git 提交痕迹）。pending 与台账都在版本历史里，攻击者要绕过 H7 须同时
伪造二者并保持链自洽——这已超出「改本地文件不留痕」的对抗强度。

## ⚠️ 证据写入顺序：真相源先行（#45，2026-10-21 立规）

#44（跨会话宽限须留安装凭证）立了之后，r146 收尾发现 R146-4 只说「下次重装补齐」——
r147 读码发现**比登记的重**：旧序「台账先写、日志最后追加」崩溃 ⇒ 台账 `lines` **超前**日志行数
⇒ `missing<0` ⇒ 三条件宽限与 pending 通道都只覆盖 `missing==1` ⇒ **无任何通道可救，永久误红**。

**r147 崩溃前缀穷举坐实**（`_temp/v31_crash.py`，模拟写入在第 k 步后崩溃的全部形态）：

| 写入序 | 崩溃前缀 missing | 门判定 |
|---|---|---|
| 旧序 ledger→pending→log | **2 个前缀 missing=-1** | **RED（反证永久误红窗存在）** |
| 新序 log→pending→ledger | 全部 missing≥+0（+1 由宽限通道救） | **4/4 PASS** |

**规则 = 证据写入顺序：真相源 → 凭证 → 锚点。**
- **真相源先写**（日志 `.installed.log` 追加）：行数只增，任何对账面最多滞后（missing≥0），滞后侧有宽限通道；
- **凭证居中**（pending）：崩溃在真相源与凭证之间 ⇒ pending 滞后 ⇒ 下次安装覆盖自愈（残留窗口见 R147-4）；
- **锚点最后**（台账）：锚点超前 = 无窗可救，必须让它只能滞后。

**机器判据**：不变式 `台账 lines ≤ 日志行数`（超前即 missing<0，永久误红形态）；
穷举验证：对写入序列的每个崩溃前缀跑门，missing<0 的前缀数必须为 0。

> 取值：`python ./_temp/v31_crash.py`（新序 0 个超前前缀 / 旧序 2 个 —— VERDICT: ALL-CORRECT）。

**教训（对 R269 侧）**：登记残留时别停在「下次自愈」的安慰上——把「崩溃时哪个字段会超前/滞后」
穷举出来，滞后可宽限、超前是死窗，两种「窗口期」强度完全不同。
