## D-A 新门必须连 live 面一起验「三态」，夹具过不等于门面可用

任何新常驻门上线前，必须各实测一次下面三态并留读数（缺一即视为未上线）：

1. **应绿态**（正常输入 ⇒ rc=0 且含 pass_token）；
2. **应红态**（构造一个该红的输入 ⇒ rc≠0，且具名点名叫到它）；
3. **不可知态**（输入面取不到 ⇒ rc=2 UNVERIFIED，**绝不与「空集」混同**）。

关键区分（本轮踩的原形）：`查询成功但结果为空` 与 `查询失败` 是两种状态 ——
前者往往意味着**该纪律已达成、命题空洞成立**（该记绿），后者是**不可知**（该记 UNVERIFIED）。
把二者混成一个 rc=2，就会造出**永远不可能绿的门**；恒红门与恒绿门同样没有信息量，
还会把真故障淹在固定噪声里（本仓 R247 的反向形态：不是「零输入记绿」，而是「零输入记红」）。

配套性能判据：live 面禁「对每个待判对象各扫一次全仓」（O(N × 全仓)）——一次建索引、多次查表，
并对超大件设上限跳过。r260 一手实测：同一扇门修前 0.2 s 级漂到 50 s 级。

## D-B 负控探针一律建在 gitignore 的 _temp/ 内

#44⑧ 要求「负控副本用完即删」，与 lessons-p0 铁律「任何磁盘直删（del/erase/rm/rmdir/
Remove-Item/os.remove）禁用、唯一通道 = handoff.py recycle」在「探针建在 tracked 目录」时会打架。
处置 = 从源头不冲突：**探针建在 `_temp/`（已被 .gitignore 排除）**，用完随手删不留痕义务；
若确需建在 tracked 目录（例如要测 git 未跟踪面），则删除必须走 recycle 通道并在台账记一行。
