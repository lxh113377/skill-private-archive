## ⚠️ 转办须挂常驻复算面（#47，2026-10-21 立规）

#46（处方须声明适用边界）立了之后，r148 的 R148-4 暴露了转办线的结构性缺口：
「第 11 类生产翻绿 = 等归属方重建 BGE」——**重建发生在哪天，本仓没有任何常驻面能自动发现**。
登记「等对方」只是许愿；对方悄悄做完（或悄悄永远不做），本仓的台账都毫无感知。

**r149 核验的两条关键事实**：
1. 归属方**早有权威陈旧判据**（`焚诀 eval/derivative_watch.stale_sources()`，比编码产物 mtime，
   现算点名 `gsap lag=7339.3s`，190 件里只报这 1 条），且已在焚诀 pre-commit 第 7 闸活链里——
   本仓看不到它而已；
2. 更硬的反例：官方 `rebuild_derived --check` 的 BGE 维**只比件数**（190=190 判齐）——
   「件数没变、内容已变」的向量陈旧它检不出。**不能拿计数对账当新鲜度终判。**

**解法 = 转诊（relay），不是代跑**：新建 `r149_derived_freshness.py`（第 56 门）
**只读 import** 归属方函数取读数（对 eval/ 零写入，重建动作仍归对方 = R269 合规），
把「等重建」变成机器读数：`face.stale_gsap` 由 True 转 False 当天 = 第 11 类生产终判闭环日。

**机器判据（转办三件套）**：每条外推提案的验收若落在对方动作上，必须同时具备——
① 本仓常驻面能读到**对方口径的**闭环读数（转诊优先：对方已有判据就 import，不造轮子）；
② 读不到数（None/异常/判据不可达）⇒ **UNVERIFIED rc=2**，禁读成新鲜（R247）；
③ 对方的无关漂移**不连坐**本仓红（`others_n` 单列告警，分级同 #35）。

**反向验证（r149 实测，两层）**：

| 层 | 变体 | 读数 | 判定 |
|---|---|---|---|
| 消费逻辑（六态注入） | 含gsap / 全新鲜 / 只他人 / None / 异常 / 不可达 | True-告警 / closed / 不连坐 / rc=2 / rc=2 / rc=2 | 全对 |
| 源侧真测性（纯函数喂假件） | 源新 1h / 源改回过去 / 空源 | 点名 lag=3600 / [] / None | 非硬编码 |

> 复算：`python 05-exec/r149_derived_freshness.py --json <件>`；
> 六态 `python ./_temp/v36_probe.py`；假件真测 `python ./_temp/v36_teeth.py`；
> lag 交叉复算（官方 7339.3s = 自算 mtime 差）在同一探针输出内。

**适用面**：不只 BGE——凡「本仓判定依赖对方重生成物」的转办件（注册表、派生索引、镜像）
都按三件套挂转诊面；对方没有现成判据时，才退而自建（并在提案里注明来源=本仓推断）。
