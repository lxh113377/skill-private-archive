**可被整体重写成一份自洽的假历史**——`seq` 单调、四要素齐、末行对齐快照，
第 54 门初版 **rc=0 放行**（r143 量化坐实，`_temp/v24_forgery.py` 可复现）。

**解法 = 哈希链**（`r138_install_hooks.py` 写入）：每行加 `prev_hash`（上一行的 `line_hash`，
首行 `GENESIS`）与 `line_hash`（对**除自身外全部字段**的规范化 JSON 求 sha256，keys 排序）。
篡改/重排/删光任意行 ⇒ 该行 `line_hash` 复算不符或 `prev_hash` 不接 ⇒ **链断**。

**机器判据**（并入第 54 门 H6，载荷约定见 `r138_install_hooks.py` 注释）：
从首条带链行起链必须完整连续；**末行必须带链，无条件**——
新安装永远带链，末行无链 = 有人删链/截断/重写（含「全 legacy」态）⇒ 判红，逼重装补链。

**r143 两抓（#32 的直接收益，两处都是判据自身的 bug）**：
1. **载荷不一致**：初版把 `line_hash` 算在 `seq` 赋值之前 ⇒ 写入即自断链
   （复算不符）；且验证端排除 `line_hash` 但包含 `seq`，两端载荷不一致。修正写入顺序。
2. **坐标系不一致**：读日志 `enumerate(f, 1)` 是 1-based，链验证按 0-based 索引 ⇒
   `first_idx=1` 时 `range(1)=[0]` 把**自己**当「之前的行」自我对照 ⇒ 误判「链裂开」。
3. **假绿分支**：初版「全 legacy 不判红」被 V2 伪造绕过（删光链字段即洗成 legacy）⇒
   收紧为末行必须带链，无条件。
