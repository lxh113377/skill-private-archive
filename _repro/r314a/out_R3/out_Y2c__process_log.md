## 改了哪些 · 为什么
- 新增 <done_criteria>（6 条二元判据）与 <verification>（8 条自检）：技能判据「没有 Done 判据＝没有终点线」；原话「弄一版」「好看起来」「上线」三处都无可判定终点，现全部二元化（部署退出码 0、线上 URL 返回 200、前后「商品名+价格」清单 diff 为空、git diff --stat 只含 assets 内图片）。
- 新增前 30% 副本：<context> 第 3 条与文末 <hard_constraints> 同内容，并写明「两处表述有差异时以更严一方为准」——依据技能首尾效应与「关键约束须落在前 30%」，与用户「放结尾」意愿并存，不改原意、不加新任务。
- 新增 <anti_patterns>（9 条禁止-替代对）：技能明示技术/执行类「禁止项比正面指令更安全」。最危险的是价格——原话「不许动商品价格」可被读成「不改字段但改展示也还行」，故把改格式化函数、改展示文案数字、改单位一并封掉。
- 新增 <scope_conflict>：「页面也要好看起来」与「只许改 assets 里的图片」按字面互斥。默认取字面（只动图片），确需越界则转提案并停止，最终报告必须复述该冲突——比擅自扩大写入面安全，比停下来等回复更符合技能「不停下来」原则。
- 新增 <stop_conditions> 与「无证据写未知」：技能抗幻觉要求；题面声明 agent 有命令行权限并要真上线，故把需外部凭据、目标不唯一、缺源图、价格与结构耦合、基线不干净五类情况写成硬停并规定报告形态。

**自评最不确定的一处** = <scope_conflict> 的字面裁定：若用户真实意图是「页面样式一起改、只许改图片那句只是针对图说的」，本 prompt 会把页面美化压成提案、交付看起来偏保守。处置理由＝硬约束字面禁令优先于推论、可一句话解除；代价＝可能少做一层。
