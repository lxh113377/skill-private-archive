# 优化后 Prompt — 超市销售 CSV 清洗脚本（交给 coding agent，可直接粘贴使用）

<role>
你是本地仓库内的数据工程 coding agent。唯一交付物：写在 `clean/` 目录里、可重复运行的 CSV 清洗脚本包。
</role>

<context>
- 输入：仓库内一批超市销售 CSV。真实路径、文件名、列名、行数、脏值形态**本 prompt 不提供**，由你在阶段 1 实测得出。
- 已知环境事实：本任务**不提供任何数据库连接凭据**，工作区为本地仓库，不联网、不连库。
- 下游用法：清洗结果之后要灌进线上库，所以产物必须「零加工可上线」；但**上线动作本身不属于本任务**。
- 约束来源：用户对「订单金额字段」与「只改 clean/ 目录」两条反复强调，按历史踩坑点处理，已转成硬约束与自检项。
</context>

<task>
做一个清洗脚本：先审计，再让脚本内建多条**结构不同**的清洗路径并全部实跑，用跑前写死的评分函数择优，产出清洗结果 + 一份待授权的生产上线工件。

- [P0-1] 审计：清点全部 CSV → 路径/行数/列名/推断 dtype/每列缺失率/重复键数/异常值样例，写入 `clean/audit_report.md`。后续一切规则只能引用这份报告里的实测数字。
- [P0-2] 候选路径 ≥3 条且机制互不重合（示例方向，最终以审计结果为准，不得照抄）：A 保守型（仅去重 + 类型规整，缺失一律不填）；B 规整型（日期/编码/单位归一 + 数值 winsorize）；C 严格型（不合格行整行剔除并入 discard log）。
- [P0-3] 评分函数先写死再跑：每条路径输出 5 项指标 —— 行守恒率、列完整率、类型合格率、重复率、金额字段改动计数（必须为 0）；按声明权重排序，入选与淘汰都记理由 → `clean/strategy_comparison.md`。
- [P0-4] 用最优路径产出最终清洗文件，并生成**不被执行**的生产写入工件：幂等 upsert SQL（文件名含 `NOT_APPLIED`）+ 人工上线步骤说明；可选另附默认 `dry_run=True` 的写入模块。
- [P1] 边界与鲁棒：空文件、单列、utf-8/gbk 编码混杂、日期多格式、BOM、千分位金额字符串 → 显式分支并在报告中留证据。
- [P1] 一条命令复跑全套（审计→候选→择优→产物），且确定性：同一输入两次运行，产物字节一致。
- [P2] 人类可读摘要 / 脏值分布表（有则更好，无不影响判据）。

防幻觉兜底：凡审计未覆盖的判断（某列是否为金额、异常阈值取多少、业务口径），必须在报告中写成「假设 + 反证方法」，禁止伪装成已验证事实；不知道就明说不知道。
</task>

<phases>
阶段 1 审计 → 检查点：`clean/audit_report.md` 存在，其中每个数字可由脚本重跑复算。
阶段 2 写死评分函数与权重 → 检查点：评分代码在跑任何候选前已定稿（文件时间戳或注释声明为证）。
阶段 3 实跑 ≥3 候选 → 检查点：`clean/strategy_comparison.md` 含每条路径的 5 项指标值与最终排名。
阶段 4 出产物 + 上线工件 → 检查点：金额字段改动计数 = 0 且 `git status --porcelain` 的新增/修改全在 `clean/` 下。
阶段 5 复跑确定性 → 检查点：连续两次运行的清洗产物 sha256 相同。
（任一检查点不过，不进入下一阶段。）
</phases>

<done_criteria>
以下全是是/否二元判据，缺一即未完成：
1. `python clean/clean_sales.py` 退出码 0，且 `clean/audit_report.md` 数字可复算。
2. ≥3 条清洗路径全部实际执行过，`clean/strategy_comparison.md` 给出指标表与排名。
3. 清洗产物与原 CSV 逐行比对，订单金额字段的改动计数 = 0，且脚本自己打印了这个数字。
4. 本任务新增/修改的文件 100% 位于 `clean/` 目录内。
5. 运行全程零数据库连接、零网络请求；不存在凭据也能跑完全部判据。
6. 生产上线工件存在且明确标注「未执行 / 需人工授权」。
</done_criteria>

<constraints>
两条死线（定义在此，文末按用户要求再显眼重复一次）：

- **D1 订单金额字段不能动**：不改名、不改类型、不重算、不填充、不四舍五入、不因其为空而删行；有空值即原样保留并列为待决项。
- **D2 只许改 `clean/` 目录下的文件**：原始 CSV 与仓库其它路径一律只读，不在仓库外新建文件。

其他约束：
- 不联网、不连任何数据库（本任务无凭据）。
- 清洗规则来自审计证据，不来自臆测的业务假设。
- 择优权重在跑候选前写死，禁止看完结果回改。
- 报告与回复用中文。
- 冲突优先级：D1 > D2 > 清洗质量指标 > 其他（「洗得更干净」与「不动金额」冲突时，不动金额）。
</constraints>

<anti_patterns>
禁止：脚本连生产库执行 INSERT/UPDATE/DELETE → 替代：只产出待授权上线工件，默认 dry-run
禁止：跳过审计直接写清洗规则 → 替代：先出 `audit_report.md` 再定规则
禁止：只实现一条路径就宣称「这样最好」 → 替代：≥3 条路径实跑 + 固定评分
禁止：跑完候选回头调权重 → 替代：权重在阶段 2 写死并留证
禁止：填补或修正订单金额（哪怕看起来明显是错的） → 替代：原样保留 + 写进待决项
禁止：静默丢弃行 → 替代：每次丢弃都进 `discard_log.csv`（行号 + 原因）
禁止：把临时文件、缓存、备份写到 `clean/` 之外 → 替代：中间产物也落 `clean/`
禁止：编造列名、行数、脏值比例 → 替代：一律引用审计实测数字
</anti_patterns>

<artifact_rules>
交付物（全部在 `clean/` 内）：
- `clean/clean_sales.py` — 主脚本（审计 / 候选 / 评分 / 择优 / 产出）
- `clean/audit_report.md` — 阶段 1 实测数字
- `clean/strategy_comparison.md` — 候选指标表、排名、入选与淘汰理由
- `clean/output/sales_cleaned.csv` — 最终清洗产物
- `clean/deploy/sales_upsert_NOT_APPLIED.sql` + `clean/deploy/README.md` — 生产上线工件与人工步骤
- `clean/discard_log.csv` — 丢弃行与待决项记录
排除（不得写入/打包）：原始 CSV 的任何改动、`__pycache__/`、`.ipynb_checkpoints/`、任何凭据或连接串、数据库文件本体、仓库根下的散落临时件
</artifact_rules>

<output_format>
按此顺序回复，勿加寒暄：
1. 文件清单（新增路径，全部在 `clean/` 下）
2. 审计摘要（≤10 行，只引用实测数字）
3. 候选对比表：`路径名 | 行守恒率 | 列完整率 | 类型合格率 | 重复率 | 金额改动计数 | 排名`
4. 选优结论 + 一句理由
5. `<done_criteria>` 6 条逐条「是/否 + 证据」（命令与关键输出行）
6. 假设与待决项清单
</output_format>
