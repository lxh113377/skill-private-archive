## 歧义与要求处置
| 歧义① 那批 CSV＝无路径/列名/脏值形态 | 按最优理解：列为 [P0-1] 审计，规则只能引实测数字；缺失即标「假设+反证」→ 交付件 <task> [P0-1]、防幻觉兜底段 |
| 歧义② 多想几种路径都试一遍择优 | 取字面＝脚本内建 ≥3 条结构不同路径并实跑；评分与权重跑前写死（防择优作弊）→ <task> [P0-2][P0-3]、<phases> 阶段 2/3 |
| 歧义③ 直接往生产库写（与题面「无凭据」冲突）| 唯一方向性改道：禁止执行 DML，改为产出待授权上线工件（`NOT_APPLIED`）+ 默认 dry-run → <anti_patterns> 首条、<artifact_rules>、<done_criteria> 5-6；保留原意「立竿见影」＝产物零加工可上线，未删该诉求 |
| 要求保留 死线位置＝末尾显眼 | 遵用户指定：文末 ⚠️ 死线块 + <verification> 自检项；<constraints> 只作定义并写明「文末再重复」，未把定义位置当改动 |
| 要求保留 不新增任务 | 交付件内无 GUI/联网/重构/性能调优等用户未要求的活；「其他调整」级别的小改动不罗列 |
| 七步闭环 ②→③ | 不反问：Step2 原则「不停下来等回答」＋本轮禁回抛 ⇒ 歧义以最优理解写进 prompt；「任务卡本轮目标」跳过＝题面只列两个交付件、无任务卡 |
