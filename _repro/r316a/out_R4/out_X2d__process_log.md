判断记录 —— 超市静态站改版请求的 prompt 优化

1. 执行环境：优化后的 prompt 交给有命令行权限的 coding agent 自动执行 → 按「AI 直接执行」优化，保留可运行的 diff 与部署验证要求。
2. 入口：请求本身就是要发给 AI 的指令文本 → 走「优化已有 prompt」链路，不是「从需求从零生成」。
3. 质量预判：无角色、无输出格式、无完成判据，仅约束部分明确、表达通顺核心意图清晰 → 判为中级，以补缺失项为主；因含多步执行与部署，另补阶段检查点、判据、自检、禁止项四类段落。
4. 歧义「想全面一点、多从几个角度反复推敲」→ 取「固定成可验收方法」这一理解：两个指定角度 × 提案-批判-修订 + 定案清单产物（见 <task> 块 3、阶段 2、<done_criteria> 4）。
5. 歧义「方法你自己定」→ 判定为让优化方定方法，故在本件写死方法，不留给执行 agent 自由发挥（同上 <task> 块 3）。
6. 歧义「只许改 assets 目录里的图片」与「必须同步更新引用路径」互斥 → 拆开：图片文件位置锁 assets，引用路径改动必须做且只改路径串（见 <hard_constraints_keep_last> 第 2 条的例外句）。
7. 歧义「直接让它自己跑完部署上线」→ 保留自动部署要求，并补线上验证判据（<task> 块 4、阶段 5、<done_criteria> 5）。
8. 保留的用户要求：图升级与页面美化（<task> 块 1/2）、多角度反复推敲（块 3）、自动跑完部署上线（块 4 + 阶段 5）、不许动价格与只许改 assets 图片（<hard_constraints_keep_last> 1/2）、两条限制写在最后（该段为约束正文末段，<done_criteria> 与 <verification> 是其后的自检附录，不是第三条约束）。
9. 改动：结尾两条的破坏性风险集中成 <anti_patterns> 的 禁止 → 替代 配对，并把可能借口逐个列举（美化/对齐/格式化/补小数位/统一位数/修正错价），使禁止项可判定而非态度化。
10. 改动：服从「放结尾最显眼」保留末段权威文本，另在 <constraints> 加一条前置提醒并声明不一致以末段为准，形成首尾呼应；这是唯一一处有意的位置重复，未把两条约束整体前移。
11. 改动：新增 <role>/<context>/<phases>/<done_criteria>/<verification>，把「完成」定义为 5 条二元判据（价格 diff 行数 0、assets 外图片文件数 0、引用 404 数 0、两份含被否决项清单、线上 200 命中新标记串）。
12. 跳过 <examples> 段：无可核验的真实素材与参考站点，编造示例会污染执行，只给判据不虚构样例。
13. 跳过 <file_structure> 段：不掌握该站实际目录，写死文件树等于制造幻觉。
14. 跳过 <context_budget> 段：文件数量未知，未达大项目触发条件。
15. 跳过 <thinking> 标签：执行类任务的推理结构已由 <phases> 检查点与 <verification> 清单承载，再加属重复。
16. 跳过图片/视频生成提示词的字段拆解、平台语法与参数适配：本请求的图片由执行 agent 本地生成或取用后落盘，不涉及文生图/图生图的平台 prompt 语法。
17. 跳过「列出多种理解并请用户纠正」的提问环节：本题只产出交付件，不得回抛提问；改为在 prompt 内直接写死取舍与例外（见 <task> 块 3、第 6 条例外句）。
18. 交付件形态自查：本体未被代码栅栏整体包裹，XML 段名直接成文；首行为标题、无本机路径与外部规范件名；正文无内部称谓与外部指针。
19. 对应关系：本记录提到的每个段名、判据与跳过项，都能在 optimized_prompt.md 逐字定位，未声称任何未落盘的段落。
