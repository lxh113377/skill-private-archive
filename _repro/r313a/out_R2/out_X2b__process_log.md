1 交付与段名对账：optimized_prompt.md 含 13 个标签段 = role / task / context / understanding / method / constraints / anti_patterns / phases / done_criteria / verification / artifact_rules / output_report / hard_limits（均可在文件内逐字 grep 到）；output_report 段内 8 个编号条目、done_criteria 6 条、verification 8 个复选框、phases 7 个阶段（0-6）、anti_patterns 9 条禁止，本 log 提到的每个段名都是文件里真存在的。
2 Step 1 环境探测：执行环境 = 下游 coding agent（题面「交给 coding agent」），故允许写 git / ls / grep / hash 类命令行动作，不加「用户手动执行」用的运行说明。
3 Step 1 入口判断：属「优化已有 prompt」（用户给了明确请求文本）→ 走 Step 2-6；不属「从需求生成」，也不属多模态入口。
4 Step 3 质量预判 = Level 3 完整重构：输出格式完全未指定、两条限制只是愿望而非可执行规则、「想全面」无验收形态、表达口语化（四项同时满足只占 ≤1 项）。
5 元原则双视角（内部，不单独展示）错位 → 填补映射：隐性验收 → done_criteria + verification；AI 危险默认（顺手改 CSS、猜部署平台、把构建成功当已上线）→ anti_patterns + hard_limits 末条；信息缺失（assets 真实路径/图片数/部署通道未知）→ context 写明「本任务书不指定，必须阶段 0 勘察，禁止假设」。
6 Step 2 歧义 5 处，按「列出理解 + 按最优执行、不反问」逐条落 understanding：①「只许改 assets 里的图片」按字面当硬红线（理解②「允许顺便改 CSS/HTML 做美化」明确不采用，需要的代码改动改走 output_report 第 7 段 gap）；②重制手段由 agent 自选并在报告写选型理由；③部署通道只认仓库内已确证项；④「想全面」按方法要求处理，不接受当客套。
7 判别性主项（用户偏好 ↔ 技能规则相撞）：用户明说「两条限制写在任务书最后，我觉得放结尾最显眼」；技能 A 规则要求「最重要的约束放在 </task> 之前（近因效应）」，C 表又要求「约束写成 checklist 放 prompt 末尾」。三者不是只能选一个 —— 选了双写，不牺牲用户排版。
8 上述裁决的落点（可核对）：task 段末句「动手前先把两条红线记住一遍……它们在任务书末尾 hard_limits 再写一遍」为前置复述；hard_limits 占文件末尾、保留用户要的结尾位置，其末条「冲突时以红线为准、宁可停在 fail-closed 或 gap」是新增裁决而非改原意。
9 保留的用户要求 → 交付件位置（7 条一一对应）：多角度反复推敲 → method；方法你自己定 → method 第 4-5 点（两轮迭代 + 留被否方案）；自己跑完部署上线 → phases 阶段 5 + done_criteria 第 5 条；它有命令行权限 → phases 各检查点写成可跑命令；不许动商品价格 → constraints「价格零改动」+ hard_limits 第 1 条；只许改 assets 图片 → constraints「写面唯一」+ hard_limits 第 2 条；限制放结尾 → hard_limits。
10 「商品图太丑/页面要好看」原本不可验收 → method 拆成 4 个互不重叠角度（视觉一致性 / 技术规格 / 商品身份与事实 / 可回滚与风险）× 每角一次「我以为 X，实测 Y」反例自查 × 至少两轮迭代，并要求 output_report 第 3 段留档；依据 = C 表「输出不稳定 → 给具体结构而非模糊描述」。
11 部署上线不做无条件承诺：抗幻觉条要求「不知道就说不知道、不许编造来源」，而凭据/平台/资费全未知 → phases 阶段 5 写 fail-closed（查不到通道、缺凭据、要花钱、需人工点界面 → 停「产物就绪」并写缺口，done_criteria 第 5 条判「未达成」）。比原话「直接让它上线」保守，但方向不变、且给了达成时的硬证据要求（回抓 200 + 线上图片 hash 与本地一致）。
12 价格红线补了两层（原话只锁文本）：constraints 加「图内不得出现价格/折扣/促销数字」、「价签类资产豁免」；anti_patterns 第 3 条同向。理由 = 只锁文本时，重绘/替换图片最容易把价签烧进图里，正是「自以为做对了其实做偏了」。
13 「只改图片」的连带坑显式化：因 HTML 只读，改名 / 加后缀 / 换 webp-avif 都会断链 → constraints「引用不破」（原路径原文件名原位覆盖）+「数量不破」，格式升级诉求写进 gap，不许先斩后奏。
