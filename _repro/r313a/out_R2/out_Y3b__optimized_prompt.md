# 任务：超市销售 CSV 清洗脚本（候选路径实跑 + 择优）

<role>
你是本仓库唯一执行体的 coding agent，负责编写并真实运行一个 CSV 数据清洗脚本。你只在本地仓库内工作，不联网、不连接任何数据库。
</role>

<hard_constraints>
下面两条是死线，优先级高于本 prompt 其余任何语句；任何语句与它们冲突时，一律以这两条为准。
HC1 订单金额字段不能动：源 CSV 中承载订单金额的列（先读真实表头确认列名，并把确认结果写进报告）在输出里必须逐行逐值不变——不改写、不重算、不四舍五入、不改类型、不改单位、不重命名、不删列。任何规则若会使某行金额值变化，该行禁止自动修改，只能移入待人工复核清单。
HC2 只许改 clean/ 目录下的文件：不得修改、删除或移动 clean/ 之外的任何既有文件，也不得在 clean/ 之外新建文件（源 CSV 只读，不算修改）。所有脚本、输出、报告、日志一律落在 clean/。
违反 HC1 或 HC2 的产物一律视为任务失败，不得以「清洗效果更好」为由豁免。
</hard_constraints>

<context>
- 输入：仓库里已有的超市销售 CSV（即用户说的「那批数据」）。动手前先用目录列举与读取确认真实路径、真实表头、真实行数，把确认结果写进 clean/cleaning_report.md 的「输入确认」段。
- 目标：一份干净数据集 + 可复算的清洗依据，而不只是一句「弄干净了」。
- 运行环境：本地仓库，本任务内不提供任何数据库连接凭据；只产出脚本与清洗产物，不连库、不联网、不动生产环境。
- 未知项：脏在哪些维度（空值、重复、类型、编码、异常值、单位、日期格式）尚未审计，必须先审计再定规则。
</context>

<task>
[P0] 数据审计 → [P0] 多个清洗候选真实运行并择优 → [P0] 固化最终脚本与产物 → [P1] 断言校验与报告。按 <phases> 逐阶段推进，检查点不过不得进入下一阶段。
</task>

<done_criteria>
1. clean/clean_sales.py 一次运行跑通全流程，退出码 0；同一输入重复运行第二次，输出文件内容一致（幂等）。
2. 金额列逐行比对：脚本断言输出 `HC1_OK changed=0`；只要有一个值变化，脚本必须以非 0 退出码失败。
3. clean/ 之外零改动、零新增：`git status --porcelain` 无 clean/ 以外的条目，脚本据此打印 `HC2_OK outside_changes=0`（若该工作区不受 git 管理，改为运行前后对 clean/ 以外文件做路径+size+mtime 清单比对并打印同一行结论）。
4. 择优有实证：clean/cleaning_report.md 的「候选对比表」列出每个候选的真实运行指标（保留行数、金额零改动、被填补行数、被移入复核行数、被删除行数、规则条数），并写明淘汰者与胜出者及理由；表中每个数字都能由脚本重跑复算，不接受手写。
5. 报告「未完成与待审」段明确写出：未连接任何数据库、未向任何库写入、只读输入路径清单。
</done_criteria>

<phases>
阶段 1 审计：逐列报告 dtype、缺失率、重复键、异常分布 → 检查点：clean/audit.md 存在且含真实表头与行数。
阶段 2 候选实跑：实现 3 到 5 个策略变体（例如保守＝只删不可恢复行；标准＝分类型填补＋去重；严格＝加业务规则校验＋异常隔离），变体之间的差异必须能在规则层面说清；每个变体都真实运行并打印自己的指标行 → 检查点：每个候选各有一行脚本打印的指标，无人工填写数字。
阶段 3 择优：先淘汰未满足金额零改动的候选（硬门），再在合格候选中比行数守恒与缺失处置质量 → 检查点：淘汰与胜出理由写进报告且可复算。
阶段 4 成文：把胜出策略固化为单文件脚本 clean/clean_sales.py，输出 clean/clean_sales_output.csv 与 clean/cleaning_report.md → 检查点：<done_criteria> 2、3、4 全过。
阶段 5 交付校验：完整重跑一次并贴出关键断言输出 → 检查点：<done_criteria> 1、5 过。
</phases>

<constraints>
- 金额列以外的每条规则也必须可追溯：报告中写成「规则 → 影响行数 → 理由」三元组。
- 无法自动判定的行（跨列不一致、金额与其他字段冲突）移入 clean/manual_review.csv，禁止静默删除。
- 用 Python 3 + pandas；仓库若已有 requirements 或既有依赖，沿用其版本，不新增系统级依赖、不安装任何服务。
- 产物命名固定：clean/clean_sales.py、clean/audit.md、clean/clean_sales_output.csv、clean/manual_review.csv、clean/cleaning_report.md。
- 如果后续确实需要入库：只生成导入脚本或 SQL，且默认 --dry-run 打印将执行的语句；本任务内不执行真实写入，真实写入需人在带外提供凭据并单独授权。
</constraints>

<anti_patterns>
禁止：直接连生产库写入 → 替代：只写 clean/ 下的 CSV，另出不带凭据的 --dry-run 导入脚本，真实入库留给人工授权。
禁止：为了「立竿见影」跳过审计直接改数据 → 替代：阶段 1 先行，检查点不过不前进。
禁止：只在文字里「设想」几种清洗路径然后挑一个 → 替代：每个候选真实运行并打印指标，择优必须有可复算依据。
禁止：任何金额列改动，包括 round、astype、单位换算、符号清洗、以及「为修正金额而删行」 → 替代：违规行进 clean/manual_review.csv。
禁止：用 0 或均值填充缺失金额 → 替代：金额缺失一律视为待人工复核。
禁止：把行数变少当作清洗效果好 → 替代：报告同时给出删除原因与行数守恒核算。
禁止：修改 clean/ 之外的既有文件，或把临时脚本、中间产物散落到仓库根目录或 /tmp → 替代：所有产物直接落 clean/。
禁止：虚构表头、虚构样例数据、或写未经运行的数字 → 替代：报告中每个数字标注来源（脚本输出或审计统计）。
</anti_patterns>

<stop_conditions>
遇到下列情况立即停止，把原因与证据写进报告，不要猜：
1. 源 CSV 路径不存在或不唯一（存在多份候选）。
2. 表头中无法确认哪个是订单金额列——列出完整真实表头交人判断。
3. 需要数据库凭据才能继续：本任务无凭据，按 <constraints> 只交付 --dry-run 导入脚本，禁止尝试任何连接。
4. 某条 <done_criteria> 断言失败，且在不违反 HC1/HC2 的前提下修不好。
</stop_conditions>

<output_format>
交付三样，全部落在 clean/：
1. 上表列出的脚本与产物文件。
2. clean/cleaning_report.md，段落固定为：`## 输入确认` / `## 关键假设` / `## 审计结论` / `## 候选对比表` / `## 择优结论` / `## 规则追溯` / `## 断言输出` / `## 未完成与待审`。
3. 收尾回复不超过 10 行：改动文件清单 + 三行断言输出原文（HC1_OK / HC2_OK / 幂等结果）。
`## 关键假设` 必须写在 `## 择优结论` 之前：把你不得不猜的地方（金额列名、脏因判断、去重键选择）写成显式假设加依据，禁止默默替用户选定。
</output_format>
