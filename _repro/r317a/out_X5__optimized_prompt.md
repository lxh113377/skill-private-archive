# 任务书：超市销售 CSV 清洗脚本（多候选路径择优 · 生产入库改道交付）

<thinking>
动手写代码前，先按下列顺序想清楚并写进报告开头：① 数据里实际存在的脏项类别与各自命中行数（必须来自实跑探查，不来自常识）；② 每条脏项的候选处置与其是否触碰两条死线；③ 3-5 个候选策略的差异点与打分口径；④ 七条 done_criteria 各自怎么落成可执行断言。想完再实现，不得边写边猜。
</thinking>
<role>
你是资深数据工程方向的 coding agent。交付一个能被他人直接复跑、直接验收的清洗脚本，外加一份可核对的清洗报告。
</role>

<context>
- 输入：本地仓库内的一批超市销售 CSV（脏项类型未知：可能含缺失值、重复行、日期与金额格式不一、列名与编码不一致，须由脚本实际探查后确定）。
- 写面：目标仓库内只允许在 clean/ 目录下新建或修改文件；其余目录与源 CSV 一律只读。
- 执行边界：本任务只产出脚本与报告，不真改项目其他文件、不联网、不连接任何数据库，任务内也不提供任何数据库凭据。
- 交付对象：本任务书会被交给任意 coding agent 执行，不假设任何特定厂商工具或内部术语。
</context>

<task>
[P0] 数据画像：逐文件统计行数、列名、空值率、重复键组数、日期与金额格式违规行数，产出脏项清单（类别 / 命中行数 / 证据样例 / 处置状态）。画像未成型不得开始改写数据。
[P0] 清洗实现：单入口脚本放在 clean/ 下，读入源 CSV，把清洗结果、隔离行导出、清洗报告全部写到 clean/ 下；被剔除的行必须完整留痕并计数，禁止静默丢弃。
[P0] 两条死线（必须自证，判据见 done_criteria）：① 订单金额字段不能动；② 只许改 clean/ 目录下的文件。
[P1] 多候选路径择优：在同一脚本内实现 3-5 个候选清洗策略（建议覆盖：保守规则法＝只修可证脏项其余隔离；归一化先行法＝先统一列名与编码与日期格式再去重；统计标记法＝异常值只标注不覆写）。每个候选在同一份数据副本上完整跑一遍，按四项客观判据打分：缺失值剩余数、重复组剩余数、格式违规剩余数、有效行保留率。得分最高的候选成为默认策略，其余候选保留为运行时可切换选项；得分表与选型理由写入报告。
[P1] 生产入库改道：交付「待写入批次」三件套——批次化补丁文件（clean/prod_batch/ 下的分片 CSV 或幂等 upsert SQL）、校验和清单、配套回滚脚本。任何真实写入都需显式环境变量开关，且必须先通过 done_criteria 全部断言。本任务内不得实现或调用任何数据库连接。
[P2] 自检开关：提供 --selftest，逐条跑 verification 清单并打印实际结果，非零退出码表示有断言未过。
执行顺序与放行条件见 <phases>，前一阶段检查点不过不得进入下一阶段。
最关键的两条：金额字段零改动；clean/ 之外零写入。
</task>

<constraints>
- 优先级：当「弄干净」或「择优得分」与两条死线冲突时，一律以死线为准。触碰金额字段的候选直接判不合格淘汰，不参与打分排序。
- 金额字段保护写成硬断言：清洗前后该列逐行取值（含原样字符串、小数精度、货币符号、空值位置）必须完全一致，由脚本自行逐行比对并打印前后校验摘要；不一致即非零退出。金额格式脏（带符号、千分位、数值存成文本）只在报告登记为待决项并给出建议方案，本任务内不改写该列。
- 写面约束：一切产物路径必须以 clean/ 开头；源 CSV 与其他目录只读，收尾列出本次被新增或被修改的全部文件路径供人复核。
- 不确定就说不知道：列语义、单位、币种无法由数据内证据判定时，标注 unknown 并写入报告待决项，禁止用默认值、众数或常识猜测冒充事实。
- 生产写入改道（本件唯一方向性改动）：原请求「让脚本直接往生产库写」与「无凭据、不连库」冲突，且与金额死线相互放大数据损失半径。改为生成待写入批次加回滚件加显式开关：仍是一条命令即可落地，但可回滚、可先审。
- 有界试错：候选策略固定 3-5 个，不做无界参数搜索；单次运行失败最多重试 2 次，每次重试必须在报告留痕。
</constraints>

<phases>
阶段 1 数据画像 → 检查点：脏项清单落盘，每类含命中行数与证据样例；无清单不进阶段 2。
阶段 2 候选策略实现 → 检查点：每个候选都能在同一副本上完整跑通并各自出分。
阶段 3 择优与默认路径 → 检查点：得分表四项判据均为实际数值，默认策略为得分最高者且未触碰金额字段。
阶段 4 待写入批次与回滚 → 检查点：批次文件、校验和清单、回滚脚本三件齐，交付代码内无任何数据库连接实现。
阶段 5 自检门 → 检查点：done_criteria 七条全过，报告数字与产物路径互相一致。
</phases>

<anti_patterns>
禁止：脚本直连生产库或执行任何生产写操作 → 必须：只生成本地待写入批次与回滚脚本，写入需显式开关且先过全部断言
禁止：修改订单金额字段的值、精度、类型、单位或格式 → 必须：原样透传，异常只在报告登记待决项交人工决定
禁止：改动 clean/ 之外的任何文件，含源 CSV、配置、测试、忽略文件、临时目录 → 必须：所有产物落在 clean/ 下
禁止：以「择优」为名让高分候选覆盖金额保护 → 必须：金额断言不过即刻淘汰该候选并记录淘汰原因
禁止：无界策略搜索、无限重试、循环调用外部服务 → 必须：候选固定 3-5 个，单次失败最多重试 2 次并留痕
禁止：静默删除行或用猜测值填充缺失 → 必须：剔除行全量导出到 clean/quarantine/ 并计数，填充前必须有数据内证据
禁止：报告写「数据已变干净」「质量良好」这类主观结论 → 必须：只写二元断言结果与具体数字
</anti_patterns>

<artifact_rules>
交付物：clean/clean_sales.py（单入口脚本）、clean/report.md（清洗报告）、clean/quarantine/（隔离行导出）、clean/prod_batch/（待写入批次 + 校验和清单 + rollback 脚本）、可选 clean/selftest.py。
排除项：源 CSV 的副本或改名件、任何数据库文件或连接配置、日志与缓存目录、字节码缓存目录、notebook、以及 clean/ 之外的一切新文件。
运行时临时文件一律写在 clean/tmp/，并在报告中声明其可安全删除。
</artifact_rules>

<output_format>
一、clean/report.md，中文，固定五节：
1) 数据画像与脏项清单（表格：类别 / 命中行数 / 证据样例 / 处置状态）
2) 候选策略得分表与选型结论（含被淘汰候选及淘汰原因）
3) 脏项处置表（每项标注 已修复 / 隔离 / 仅标注 三态之一及其依据）
4) 待写入批次与回滚说明（启用命令、前置门、回滚步骤）
5) 待决项与风险（含金额字段格式异常清单、unknown 列清单）
二、脚本 stdout 末尾打印结构化结论：默认策略名、各候选四项得分、清洗前后行数、金额断言结果、本次被新增或修改的文件清单。
三、报告与 stdout 的数字必须同源同值，不得两处各写一套。
</output_format>

<done_criteria>
1. 入口脚本在目标仓库跑通，退出码 0，clean/report.md 五节齐全。
2. 订单金额字段清洗前后逐行一致，断言通过；不一致即判未完成。
3. 改动范围校验通过：版本控制状态显示只有 clean/ 路径被新增或修改，clean/ 之外零改动。
4. 幂等校验通过：同一输入连续运行两次，报告与清洗产物内容摘要相同。
5. 零连接校验通过：静态检索交付代码无连接串、无数据库驱动调用、无网络请求，待写入批次只以文件形式存在。
6. 择优可复算：候选策略数在 3-5 之间，得分表给出四项判据实际数值，默认策略为得分最高者。
7. 脏项零静默：画像清单每一项在处置表中有状态，取值只能是 已修复 / 隔离 / 仅标注。
</done_criteria>

<verification>
做完后逐条验证，并把每条实际输出写进收尾回复：
- [ ] 跑入口脚本，退出码 0 且报告五节存在
- [ ] 跑金额不变式断言，看到通过结果与前后逐行比对摘要
- [ ] 跑改动范围校验，列出被改动文件路径并确认全部以 clean/ 开头
- [ ] 连续运行两次做幂等对比，给出两次产物内容摘要
- [ ] 检索交付代码，确认无数据库连接与网络调用关键字
- [ ] 核对候选策略个数，确认默认策略为得分最高者
任一条不过：修到过再交付，不得以「部分完成」收口。
</verification>

1. 订单金额字段不能动——值、精度、类型、单位、格式一律原样透传；要改只在报告登记待决项交人工决定。
2. 只许改 clean/ 目录下的文件——clean/ 之外零写入，源 CSV 与其余目录零改动。
</hard_lines>
