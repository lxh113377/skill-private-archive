# 派发模板增补 · r319：交付物形态纪律「零内部引用」例句化（paste-clean 半程→全程）

背景：r316 立的「零内部引用」是**禁令式**（不许有 X）；R4 盲评语义核判出 0/4、R5 判 2/4——
过与不过取决于臂自发。r319 起改为**给例句**（禁令+正例+反例三件套）。

## 写进臂 brief 的例句块（task 类交付通用）
```
【形态纪律：交付件必须可直接粘贴给下游，零派发链内部引用】
正例（合规）：复核动作写给执行 agent 自己——
  「执行任何写入动作之前，先逐条复核 <scope_locks> 与 <stop_conditions>，用命令输出确认路径与权限一致；
   不一致就停止并报告。」   ← 主语是执行 agent，动词是它的动作
  「第 0 步（动手前必做）：跑 `git status --porcelain` 确认改动面只含 assets/，否则停止。」
反例（违约，一条即 fail）：
  「Review the scope locks … before pasting」          ← 直呼粘贴者=派发链读者
  「生产写入改道（本件唯一方向性改动）：原请求…」      ← 编辑手记，以对照原请求为读者
  「优化前 / 核心改动 / 其他调整」段落                  ← 属于 process_log，不属于本体
  首行放本端文件路径或规范件名 / 本体被 ``` 整对包住
边界：作用域复核**必须存在**（rubric item6），只是措辞主语=执行 agent；修订权写「与实况不符则停止上报」，
禁写「改本段即可」（那是把文档主人当成读者）。
```
## 自检口径（臂收尾必报）
- 段名 missing 数（代码核对）+ 段名形态声明（尖括号 / ## 标题）；
- 元评注 grep：把上列反例词 + 本端路径/称谓/件名做成**一份清单随 brief 下发**（臂 grep 自己）；
- 自报哈希钉算法（sha256 前 12）。
