## 2. 七步闭环：问题不在"覆盖率低"，在"关键节点缺席"

表面上只有 4 个 skill 声明七步闭环，但并非所有 skill 都需要。真正的结构性问题是：

> **`A-project-handoff` 与 `A-get-memory` 恰好是七步闭环的 ④ 和 ⑦，二者 `七步` 字样 0 命中。**

即：闭环的**两端节点自己不知道自己在闭环里**。后果是任何一环改动都可能不被下游感知。

**建议（按优先级）**

| # | 动作 | 目标文件 | 验证 |
|---|---|---|---|
| W-1 | ④⑦ 两个节点补"本 skill 在七步闭环中的位置"声明 | `A-project-handoff/SKILL.md`、`A-get-memory/SKILL.md` | `Select-String '七步' -Path <两者>` → 命中且指明 ④/⑦ |
| W-2 | 收尾类 skill 补声明 | `A-get-memory`（⑦ 反哺）、`skill-midtask-recheck`（中途重探） | 同上 |
| W-3 | 不要求全量铺开 | 其余 skill | — |

> 不建议给 102 个 skill 全加七步声明——多数 skill 是工具型而非流程节点，加了只是噪声（呼应 R198.2 广义噪声）。

## 3. footer 协议：四处重复 → 收敛为单源 + 指针

**现状**：同一套 footer 文法在 4 处各写一份，虽互标"唯一真相源"仍属双写：
- `A-memory-start/SKILL.md:69`（三铁律内联）
- `A-memory-start/SKILL.md:93`（Step 4.5 内联）
- `A-get-memory/SKILL.md:166-170`
- `A-get-memory/SKILL.md:292`

**收敛方案**
| # | 动作 | 说明 |
|---|---|---|
| F-1 | 保留 `A-memory-start/references/reply_footer.md` 为**唯一完整文法** | 已是单一真相源，不动 |
| F-2 | 上述 4 处内联段落 → 替换为一行指针 | 形如：`footer 文法见 A-memory-start/references/reply_footer.md（唯一真相源，禁在此复述）` |
| F-3 | 门禁校验 | `upgrade_footer_gate.py` → `[GATE:evolution-pass]`；改动后必跑 |
| F-4 | 新增 skill 时 | 只允许出现指针行，不允许复制文法 |

**收益**：4 份 → 1 份，消除后续版本漂移（历史上 R216d 已证明"文案匹配必然随版本漂移失效"）。

## 5. direct_map 直连误命中修正

**实测案例**：查询「为优化我的所有自建skill及其所搭载的工作流提出建议」→ `direct_hit=vp-perspective-audit`，score=1.0。

**根因（已定位）**
1. `vp-perspective-audit` **缺「何时不用本 skill」负向边界**——而同族 `skill-hitrate-full-audit:19-23` **有**该列
2. 其 description L3 含「适用于任何多agent系统的质量检查」→ 触发面覆盖整个审计族

**修正步骤（严格按序）**

| 步 | 动作 | 命令/位置 |
|---|---|---|
| D-1 | 给 `vp-perspective-audit` 补负向边界段 | `D:\global_skills\vp-perspective-audit\SKILL.md`：在 L241-249「与其他技能的协作」前加「## 何时不用本 skill」，示例：「仅当需预判 agent 行为链/心智模型时使用；命中率审计→skill-hitrate-full-audit；提示词审计→prompt-system-audit；数据层修复→data-layer-consistency-fix」 |
| D-2 | 收窄 description | L3 删「适用于任何多agent系统的质量检查」这类全族覆盖表述 |
| D-3 | 改 `_DIRECT_MAP_FALLBACK` | ⚠️ **正样本必须排在被 `NEGATIVE_TAG_MAP` 拦截的宽 pattern 之前**（R20 时序铁律）——否则负样本只产生"让位"而非"接管"，意图仍落 BGE 摇摆 |
| D-4 | 同步 | `save_direct_map.py --force` |
| D-5 | 回归 | `unified_router.py --json --timeout 15 "<原查询>"` → 确认落审计族具体 skill；同时回归旧正例与被拦宽 pattern |

**同类风险**：`openclaw-dual-gate-quality-audit` description 同样无触发词、无边界声明，建议一并检查。

## 6. 系统性建议：让闭环可度量

当前闭环三件套**无法被机器度量**（只能靠精读时 grep）。建议把三项加进 `01-scan/scan_all.py` 的扫描维度：

| 新增字段 | 判据 |
|---|---|
| `has_seven_step` | 正文含「七步」且指明所处环节 |
| `has_footer_ref` | 含 footer 指针行（指向 reply_footer.md）|
| `has_gate_decl` | 含门禁命令声明（`门禁命令: <脚本路径>`，声明全文唯一、冒号后纯路径）|

**收益**：落地率从"每次审计靠人 grep"变成**每次扫描自动出数**，后续可跟踪趋势（当前基线：3.9% / 2.0% / 24.5%）。
