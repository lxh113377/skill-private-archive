# 后续维护规范 — skill 季度巡检机制 v1（r113 立）

> 项目：自建skill优化 ｜ 权威源：D:\global_skills ｜ 立规轮：r113（2026-10-18）
> 实现件：05-exec/r113_quarterly_audit.py（单命令）；产物：06-benchmark/quarterly/<季度>/
> 关联：需求 5「建立长效的 skill 定期巡检机制，每季度扫描版本与替代方案」

## 1. 为什么要建这个机制（一手，不是模板）

| 事实 | 证据 |
|---|---|
| 第 19 维（版本落后面）到 r112 才建起判定面 | 06-benchmark/全量对标报告_r112_*.md §1.1（此前 182 件里 0 件可判） |
| 此前没有巡检节律 | r97 §4 P4 只把「twelve_face 季度重测」写在散文里，无工具、无产物落点、无判据 —— 没人可复跑 |
| 「更优开源替代是否出现」是一个**会随时间变化**的问题 | 上游仓在动：本轮实时取证 spec-kit push=2026-10-16、AAS push=2026-10-17（sickn33/agentic-awesome-skills）⇒ 一次判定不足以长期成立 |

⇒ 结论：**没有节律的判定等于一次性判定**。本机制把「每季度问一次」钉成单命令 + 落盘产物。

## 2. 巡检节律与触发条件

| 触发 | 时点 | 动作 |
|---|---|---|
| 定期 | 每季度首周（1 月 / 4 月 / 7 月 / 10 月） | 全链巡检：05-exec/r113_quarterly_audit.py |
| 事件 | 用户报「某 skill 不好用 / 落后了」 | 对该件单跑 r112_swap_gate.py 做定向裁决 |
| 事件 | 上游仓 release / 大版本升级（人工发现） | 立即跑巡检并把该件列入升级队列 |
| 常驻 | 每轮 run_gates（35 门） | provenance_face 离线守结构面（不依赖联网） |

## 3. 巡检扫什么（六段，全部复用既有判据，不重造）

| 段 | 判据件 | 产出 | 判什么 |
|---|---|---|---|
| ① 身份 | r112_provenance_scan.py | provenance.json | 四档 declared / inferred / self_built / unknown + 守恒 == 182 |
| ② 关系 | r112_upstream_probe.py | upstream.json | 六态内容寻址（identical / same_content / upstream_ahead / local_ahead / diverged / unrelated） |
| ③ 裁决 | r112_swap_gate.py | swap_gate.json | 五态（UP_TO_DATE / UPGRADE_SAFE / LOCAL_AHEAD_KEEP / UPGRADE_REVIEW / UNVERIFIED）+ 盲区具名 |
| ④ 结构 | r112_provenance_face.py | 退出码 | 离线结构判据（台账不空转 / 有身份必入册 / unknown 禁登记 / 守恒） |
| ⑤ 元数据 | gh api repos/<R> | audit.json 的 upstream_meta | 11 个上游仓的 stars / pushed_at / license / open_issues / archived |
| **⑥ 替代候选**（r114 新增） | **r114_replacement_scan.py** | **replacement_matrix.json** | **182 件逐件 3–5 个替代候选 + 五维评分；四态 MATCHED / FAMILY_ONLY / NO_OS_CANDIDATE / UNVERIFIED** |
| **⑦ 任务质量**（r114 新增） | **r114_quality_ab.py** | **quality_ab.json** | **99 条 query 的任务级路由基准：Top-1 / Top-3 / 命中率 / P / R / 误触发 + Wilson 区间 + 与基线的可比性判定** |

> 取值：python 05-exec/r113_quarterly_audit.py --quarter <NNNNQN>
> **为什么补 ⑥⑦（r114 一手）**：原五段只答「我这份是不是上游旧版」（同源问题），
> 答不了「有没有别的更好」（替代问题）与「任务质量有没有变」（任务问题）。
> ⑥ 补替代、⑦ 补任务质量；两者都不与①–⑤重叠（见 §7 分工表）。

### 3.1 ⑥ 替代候选段：判定规则（r114 立）

| 巡检结果 | 判读 | 动作 |
|---|---|---|
| MATCHED（≥3 个 skill 相关候选） | 有可讨论的替代对象 | 进「候选裁决」队列，按迁移方案 §4 的 C1–C6 六条判「是否真更优」 |
| FAMILY_ONLY | 找到同类但无对应件 | 只登记，**不进换装队列**（改进只能自建） |
| NO_OS_CANDIDATE | 开源侧无对应件 | **禁进换装队列**；若表现差只能自建改进 |
| UNVERIFIED | 取数面不可用 | 禁读成「无替代」（R247）；下季重跑 |
| 候选仓 archived=true 或 pushed_at 超 12 个月 | 候选已停摆 | 从该件候选面剔除并具名登记 |

### 3.2 ⑦ 任务质量段：判定规则（r114 立）

| 巡检结果 | 判读 | 动作 |
|---|---|---|
| Top-1 相对基线提升 ≥30% **且** Wilson 区间分离 | 可写「质量提升 ≥30%」 | 登记为已达标，更新基线 |
| 区间重叠 | 幅度落在抽样抖动内 | **禁止**写「提升」；只记实测值 |
| Top-1 下降且区间分离 | 真实退化 | 先查是否 triggers/frontmatter 被改坏，回滚该批 |
| 基准跑不起来 / 解析不出 | 判据面失效 | rc=2，禁记绿；先修基准再谈质量 |

## 5. 判定规则（巡检发现变化后怎么办）

| 巡检结果 | 判读 | 动作 |
|---|---|---|
| 出现新候选且交集 ≥ 0.15 | 该件重回同源判定面 | 从 UNVERIFIED 名单移出 ⇒ 列入 UPGRADE_REVIEW 队列 |
| 关系 = upstream_ahead / 上游增量 > 本地增量 | 有净收益 | 进升级队列（P1），按 r113 迁移方案 §2 流程合入 |
| 关系 = local_ahead / 本地增量 ≥ 上游增量 | 本地已增强 | KEEP_LOCAL，禁自动覆盖（R2） |
| 关系 = identical | 无差 | UP_TO_DATE，不动 |
| 上游仓 archived = true 或 pushed_at 超 12 个月 | 该上游已停摆 | 从候选源清单移除并登记（防拿死仓当替代） |
| 上游 license 变为 UNLICENSED / 更严 | 合规风险 | 停止对该仓的合入，登记待裁 |
| 四档之和不等于 182 / 台账空转 | 判据面自身失效 | 先修判据（R263），禁改数据凑绿 |

> 取值（记录现值的命令，禁硬编码）：git -C D:\global_skills rev-parse --short HEAD；python 05-exec/r113_quarterly_audit.py --quarter <NNNNQN>

## 6. 失败语义（反「取数失败销毁证据」）

| 情形 | 行为 | 退出码 |
|---|---|---|
| 六步全通过（r114 起：①–⑦ 段均可用） | 原子替换主产物，删 sidecar | 0 |
| 任一步失败（含网络抖动） | **主产物原样保留**（上一季好件不动），失败痕迹入 audit.error.json | 2 |
| 零输入面（provenance / replacement / quality 产物缺失） | 同上 + face_reason 具名 | 2 |

根据：r112 一手实测（一次网络 EOF 把 14KB 好证据覆写成 280B 失败桩，导致已升级件被读回 UNVERIFIED）⇒ r112 cache_guard_fixtures 常驻门 + r113 cache_guard_face 常驻门（35 门之一）。
本件是 K-4（把该范式推广到其它取数脚本）的第一件落地。

> 取值：python 05-exec/r113_cache_guard_face.py（须印 [CACHEGUARD:PASS]）

## 7. 与既有机制的关系（分工，不重叠）

| 机制 | 管什么 | 不管什么 |
|---|---|---|
| 本巡检（季度，①–⑦ 段） | 上游版本（①②③④⑤）+ 替代候选（⑥）+ 任务质量（⑦）的外部/基准扫描 | 仓内规则一致性 |
| run_gates 35 门（每轮） | 仓内判据 / 契约 / 结构 | 上游可达性（provenance_face 刻意离线）；不跑 99 条 query 基准（太慢） |
| A-skill-manager | skill 文件同步与注册表检测 | 上游版本比对；替代候选检索 |
| A-project-handoff | 记忆与体量治理 | 上游内容；任务质量 |
| fenjue eval（焚诀侧） | 路由机制实现与调优 | 本仓不擅改焚诀 eval（只读红线）；本仓只**度量**不实现 |

> **⑥⑦ 与 fenjue eval 的边界（r114 立，防越界）**：`r114_quality_ab.py` 只**调用**焚诀
> `eval/skill_hitrate_eval_v2.py` 并把结果结构化落盘，**不修改**焚诀任何文件（eval/ 只读红线）。
> 路由算法本身的改进属焚诀侧归属，本仓只在 `06-benchmark/质量提升度量_r114_*.md` §5 登记候选改法。
