## 4. 「是否真的更优」的裁决判据（本轮新立，防 D3 被违反）

单靠五维总分 **不得** 判更优。必须同时满足：

## 附录 B（r270 追加）· 阶段 C 受管根落地的两条硬纪律

> 追加理由：r266 的一次受管根落地把**整树**卷进提交（705 文件/588 删除），而当时的复核只查了「打算改的那一处」。

### B.1 提交后必须复核提交自身的文件清单（R269-4）

```
git -C D:/global_skills show --stat <sha>          # 文件数与增删行
git -C D:/global_skills show --name-status <sha>   # 逐件状态；与你的预期清单逐条对齐
```

- **为什么**：`rule_editor` 的 commit 按**整树暂存**提交 ⇒ 当时工作树里**他人在途的脏状态会被一并卷进你的提交**。
  一手：`079b91f3`（提交信息 `[rule_editor] insert (test-driven-development/SKILL.md)`）实测
  **705 files changed, 3674 insertions(+), 172902 deletions(-)**，其中 `--diff-filter=D` 计 **587 条删除**。
- **代价**：其中 **535 件仍在盘但被移出 git 跟踪** ⇒ 克隆 / 换端 / `git clean -fdx` 后即丢；
  **52 件盘上早已不存在**（该提交只是记录了他人已完成的磁盘删除）。
- **做法**：提交前先记 `git -C D:/global_skills status --porcelain | wc -l` 并把该数写进提交说明；
  提交后立刻跑上面两条命令，清单不符即停下、登记、再动。

### B.2 受管根提交有「新文件数」硬闸：≤ 20 / 提交（实测）

```
[GATE:sharedvol-fail] FAIL | 暂存面含 71 个新文件（>宽暂存上限 20）⇒ 疑似目录级 add 卷走他人未入库件
```

- 恢复/迁移大批文件时**必须分块提交**（本机实测每块 20 件可通过；失败时按块二分到 1 件）。
- 闸门设计意图 = 防「目录级 `git add -A` 卷走他人未入库件」⇒ 与我们上面的教训同源，故**不要试图绕过**，
  而是把「显式路径清单 + 分块」写进流程。
- 取值：`git -C D:/global_skills add -- <显式路径>` 后 `git -C D:/global_skills commit -F <说明>`；
  被拦时 `git reset -- <同一批路径>` 再分块。

### B.3 一次落地的最小自证清单（把上面两条与既有门禁串起来）

1. `git -C D:/global_skills show --stat <sha>` 文件清单 == 预期；
2. `git -C D:/global_skills merge-base --is-ancestor <sha> HEAD` = 0（防并行 rebase 甩出）；
