## 2. 方法与脚手架校验（先自证，再报数）

`unified_router.route(query, enable_memory=False)`、`score = 命中加权和 / n`、并暴露 `max_achievable`。
在内存里把那两条直连规则的 value 改成 `meeting-intelligence` / `brainstorming`（重建 list，因条目是 tuple），
前后各跑一次 `evaluate('layered')`。

**两项自证（缺一即数字不可信）**：

| 自证 | 要求 | 实测 |
|---|---|---|
| 脚手架校验 | 基线须复现 `score=90.1 / hits=276 / n=291 / max_achievable=95.2` | **全部复现** ✓ |
| 补丁控件 | 补丁后 `direct_route` 的返回值必须变（否则是空补丁）| `Notion 会议准备`：`NONE` → **`meeting-intelligence`**；`灵感枯竭帮我发散一波点子`：`story` → **`brainstorming`** ✓ |

| 量 | 基线 | 反事实（内存修两条规则）| 变化 |

> 取值（本节数字）：0.6 = §3 表两次 `evaluate('layered')` 的 `score` 之差（90.7 − 90.1）；7 条 = `06-benchmark/quarterly/2026Q4/route_miss_attr.json` 的 `face.real_n`；2 条 = §4 表中标 ✅ 的行数（按同一测试集前后 `results[].router_top1` 比对）。

## 6. 上界补充测量（r245 追加）：7 条**全修**也只到 92.5，上限 95.2 靠修真错**够不到**

§3 只答了「修那两条」的效果。为把目标之问答完整，再测一个**上界性反事实**：把 7 条 REAL_MISS **全部**强制成期望件后 L1 能到多少。

| 情形 | weighted score | hits / n | 距上限 95.2 |
|---|---|---|---|
| 现状 | **90.1** | 276 / 291 | 5.1 |
| 只修那 2 条真错配 | **90.7** | 278 / 291 | 4.5 |
| **7 条 REAL_MISS 全修**（上界性反事实）| **92.5** | 283 / 291 | **2.7** |

⇒ 三条读数合起来的结论：**修那两条只拿回 0.6；修完全部已知真错也只到 92.5**，
而评测上限 95.2（= `max_achievable`，由 `total_w/n` 决定）**仍差 2.7** —— 这 2.7 不在 REAL_MISS 里，
而在 8 条 `STALE_EXPECT`（期望件既不在注册表也不在盘上 = 题面过期）。⇒ **剩余缺口属题面卫生，不属路由质量**。

> 取值：`python -c` 进程内 `import frozen_blind_eval as FBE, unified_router as UR`；基线 `FBE.evaluate('layered')` = 90.1/276；
> A 组 = 重建 `direct_layer.DIRECT_MAP` 换那两条 value 后再 evaluate（90.7/278）；
> B 组 = 用 `UR.direct_route = lambda q: SEVEN.get(q) or orig(q)`（SEVEN = 7 条 query→期望件）后再 evaluate（92.5/283）；
> 8 条 STALE_EXPECT 读 `06-benchmark/quarterly/2026Q4/route_miss_attr.json` 的 `face.stale_n` 与 `rows[].state`。

> ⚠️ B 组是**上界性**反事实，**不是可落地的修法**：它直接强行指定 top1，只为回答「全修能到多少」。
> 可落地的两步仍是 §4 的「修两条真错配」（+0.6）与「3 条策略分歧的裁决 + 2 条 tag/BGE 路径」。
