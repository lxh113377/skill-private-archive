## 2. 逐项差距说明（含对应模块与量化）

### 2.1 功能模块覆盖
- 对应：本工作流 05-exec 补丁链 ↔ superpowers executing-plans；install/update 面 ↔ gh-skill（空白）。
- 量化：本地 169 vs superpowers 16 / anthropics 19，数量级 10×；r60“37 条无近邻”0 件可换装（`capability_gap_r60`）；r61 语义探针 5/5 被覆盖。
- 可借鉴：gh-skill `pin/provenance/update --all` 三件套是唯一功能形态缺口，但属分发目标293k/179k量（与对手同量级）；对策见 H-3。

### 2.2 技术架构
- 对应：A-memory-start 注入（24,816B）↔ superpowers SessionStart hook（含 compact 重注入）。
- 量化：24.8KB vs 3.1KB ≈ **8×**（r61 时约 20×，本轮入口又 -2.5%，持续收敛）；hook 面本体系仍为 0。
- 可借鉴：最小 hook 探底（≤1KB 强制声明 + compact 重注入），平台不支持则落盘豁免证据（P1-3）。

### 2.3 实现方式
- 对应：rule_editor+gates ↔ gh-skill `--fix` + provenance 随文件。
- 量化：description 字段覆盖 169/169（100%），但双要素（做什么+何时用）抽样仅 **4/9（44%）**；A-memory-start 33 字无“何时用”信号（入口技能路由第一印象最弱）；local-asr 折叠行方法学低估（单行正则局限，已声明）。
- 可借鉴：anthropics 双要素门 + gh-skill `--fix` 自动修形态（H-1 全量落地）。

### 2.4 性能
- 量化：入口 25,456→24,816B（-640B，-2.5%，今测）；路由 1.3s 含 sklearn 0.91s 税（PERF-P0-1 在途，不重复立项）；`eval/_cache` 113MB 无淘汰（PERF-P0-2 在途）。
- 可借鉴：daemon 常驻不抄（单人规模收益为负，维持 r61 裁定）。

### 2.5 可扩展性
- 量化：唯一可扩展性缺口 = description 质量门 0→1（169 件从未机器审计双要素）；gh-skill 证明“任意仓即市场”的扩展天花板（search→install→pin→update 闭环）。
- 可借鉴：H-1 description 门 + H-3 provenance 钉选形态（只钉本仓自有件，不碰分发）。

### 2.6 维护状态
- 量化：本仓今日 3 提交 + gates 25/25（`14c6346`）；对手 superpowers Issues 144/293k★（万星 issue 比 0.49，治理极强）；anthropics Issues 387/PRs 999（社区吞吐大，57 commits 说明合并且慢）。
- 差距：无社区兜底 + 无跨会话 issue 跟踪（靠门禁自证）；r61 红灯（retired_face）今日提交信息显示已修复转绿（以 gates 25/25 为准）。

### 2.7 文档
- 量化：对内 51 MD + 86 JSON（本报告为第 52 件 MD）；入口 README 挂 06-benchmark 链接待同步（§4 M-1）；对手 superpowers docs/50 文件与我方体量同级。
- 可借鉴：句柄化引用已落地，无新增；对外站/双语仍不做（X-2）。

### 2.8 适用场景
- 甜蜜点：单人 + Windows + 多端 + 长期记忆 + 垂直域（四对手无一家同时覆盖；ruflo 明示 POSIX only，反衬 Windows 原生优势）。
