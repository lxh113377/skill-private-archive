```
repo, rel, rel_strength, fc_caliber, score5{fc,eff,compat,docs,community}, score_total,
**stars, pushed_at, license, archived**, skill_md_n, skill_md_exact_n, ..., description
```

真正缺的是：**没有任何判据会在它下次变坏时报警**。本轮补这个。

## 3. 新守卫顺带暴露的真缺口：143 件受限许可里 86 件「无正文级核实」

| 许可值 | 件数 | 说明 |

| `NOASSERTION` | **86** | GitHub API 的 spdx_id 字段不可信（R261-6 已立过账）⇒ 需读 LICENSE 正文归类 |
| `AGPL-3.0` | 42 | 真受限（禁合入 copyleft 上游正文，R113-3） |
| `UNLICENSED` | 9 | 无可信许可 ⇒ 禁合入 |
| `GPL-3.0` | 5 | 真受限 |
| `CC-BY-SA-4.0` | 1 | 真受限 |

**已有覆盖**：`06-benchmark/license_body_r262.json` 只抓了 **20 仓**（`targets_n=20 / ok_n=20`）。
⇒ **86 件 NOASSERTION 里绝大多数没有正文级归类** ⇒ 它们的「合法可用性」判不了。
这不是我这条守卫的問題，是 **R261-6 的覆盖面缺口**：r262 只做了 20 仓的正文抓，没扩到全量。
