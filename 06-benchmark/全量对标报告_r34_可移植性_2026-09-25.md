### 1.1 四条结论

**① 这是本体系第一处「可测地落后于全部对手」的维度，且差距是量级差（29.3% vs 0–7%）。**
前三维（CI 存在性 / CI 有效性 / 发布面）的结论都能落到"定位差异、不必照抄"；
这一维不行 —— 三家对手抽样**零命中**，说明「技能文件不写死本机路径」在 Agent Skills 阵营里是**普遍做到的基线**，不是某家的特色。

**② 最该优先修的不是"盘符"，是 P3「账号名明文」。**
盘符路径（`D:\global_skills`）是本体系 **junction 单源架构的承重件**（权威源就在那儿，写死是有意的，AGENTS 里明文规定"路径禁用 `~` 展开，必须写完整路径"）⇒ **P2 不该进改进队列**。
但 P3（把 Windows 账号名 `37533` 抄进 25 个技能正文）不同：它**不承载任何机制**，纯冗余，且是**隐私面** —— 本体系目前"对外文档为零"所以尚未外泄，一旦任何技能被分享/上架就直接带出账号名。
⇒ 精确修法：P3 归零，P2 保留但须与"降级路径声明"成对出现。

**③ 对手里已经有人把这个做成了门禁，我们只有棘轮的一半。**
mycelium 有 `personal-pii-scrub.yml`（35,973 B 的 workflow 原文已在 `06-benchmark/ci_evidence/`）专门拦"名字 + vault 路径"落进公开件，
配 `template-purity.yml` 管"类型化形状"。⇒ 借的是**「机器身份/PII 必须有门禁，不能靠自觉」**这条机制，不是它的正则。

**④ 本体系并非无动于衷，而是**门禁管错了对象**：焚诀有 C20「技能可移植性棘轮」，
但它管的是 *inline 绝对路径条数*（r31 实测该门正被 `ican-frontend-design-system` 1→4 判红），**管不到账号名明文**。
⇒ 本轮 H-2 直接补一个只降不升指标 `username_in_skill_files`（基线 25），把这条落后**纳入既有棘轮**，
而不是再建第 7 道门 —— 复用既有门禁是本仓 R236/反重复造的一致口径。

## 5. 事故与自纠登记（本轮 4 条，全部指向自己）

1. **我用 Edit 做接线时把 `memory/AGENTS.md` 截成 0 字节。** 一个带 `if False else` 链的 python 写文件表达式最终求值成空串 ⇒ `open(p,"w")` 立即清空目标。
   处置：`stat` 确认 = 0 → `git checkout HEAD -- memory/AGENTS.md` 精确恢复（10,777 B，与 HEAD 全等，r33 内容完好）。
   ⇒ 立规（本轮已生效）：**写文件脚本禁止内联复杂条件表达式**；文件改动一律用 Edit 工具或"先算好字符串再单次 write"。
   这是本仓「破坏性操作需备份 + Git」前提在本轮**救回自己**的实证 —— 没有 git 基线，这条铁律文件就永久丢了。
2. **变异 harness 自身是坏的，且坏的方式正是"看起来通过"** —— 首版用 `mm.spec.loader` 触发 `AttributeError`，被 `except` 分支记成"变异致不可加载（算拦住）"，四条变异**全是这么"过"的**。
   修 harness 后诚实报 **caught=2/4**，再补 M2（需"有内容但无极性词"样本，空文件走的是另一分支）、M4（只改 CLI 退出码，函数级断言永远测不到 ⇒ 必须真起进程）两条专属反例，才到 4/4。
   ⇒ **加载失败不得计功**；每条变异要有"只有它能变红"的断言（r32 立的规矩，本轮第三次用到自己身上）。
3. **夹具的测试文本自身不合格** —— 原写"允许直接删除…"，`允许` 不在 NEG_RE 词表里 ⇒ 候选侧被抽出 0 条规则 ⇒ 判 UNVERIFIED 而非 CONFLICT，a2/a4/a9/层b 四例连锁红。
   ⇒ 造反例文本前先看判据词表，别凭语感写"否定词"。
4. **两处 ASCII 引号嵌套写崩新脚本**（`指到"正在写的文件"` 落在双引号串内）⇒ SyntaxError。
   修完加了 `ast.parse` 前置校验，并把"AST OK 再跑"固定成本轮动作。另清掉自己留下的 `len(dirly) if False else len(dirty)` 死表达式。
