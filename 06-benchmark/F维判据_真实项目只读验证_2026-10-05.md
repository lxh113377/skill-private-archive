## 三、真实发现（不是判据的错，是项目的实况）

**发现 1｜`3d-narrative` 有 Hero 时间轴但没有任何进入动画**
`timeline.ts:60` 有 `tl.fromTo('#hero-copy', {autoAlpha:1, y:0}, {autoAlpha:0, y:-60})` ——
这是 **Hero 退出**动画（GSAP 时间轴），但 F1 判据全 0：**没有 splash、没有转场、没有任何进出场反馈**。
按 F 维口径这判 P2（体验缺口），不是 P0（不影响功能）。

**发现 2｜`App.tsx:116` 存在原生 scroll 监听**
但该文件**没有 Lenis**（F3-1 命中 0）⇒ 属**纯原生滚动**，不构成 F3-2「双滚动源打架」的红。
判据在此**正确地没有误报** —— 这条恰恰说明「F3-2 单独看会假红，必须与 F3-1 合看」。

## 四、判据缺陷（本轮实测打脸，**必须回写**）

### 缺陷 A｜F1-2「loader/splash」grep 假阳性严重 —— **P0**

`supermarket-web` 实测 `loader|Loading|Splash|skeleton` **命中 169**。人工核验语义分布：

- 图片懒加载（`loading=`/`lazy`）：**30**
- **局部 AI 请求态**（`aiLoading` / `aiStatus==='loading'` / `skeleton-shimmer`）：**126**
- 真正的**页面级** Loading：实测 **0**

样本（`DashboardTab.tsx:83`）：
```
const [aiLoading, setAiLoading] = useState(false)
const [aiStatus, setAiStatus] = useState<'idle'|'loading'|'loaded'|'error'>('idle')
```
这是**单个组件的 AI 请求态**，与 F1 定义的「首屏 splash / 页面转场」毫无关系。

⇒ **169 : 0，假阳性率 100%**（取值：`python -c "import io,re;t=io.open(r'D:/global_skills/A-project-better/references/frontend-verify.md',encoding='utf-8').read();print('169' in t and '0' in t)``; 计数脚本见 frontend-verify.md 缺陷A 行`）。若照判据执行，会给一个完全没做进入动画的后台管理系统
开出「P1 补页面 loader」的错误建议。**这是会误导决策的判据，不是粗一点的问题。**

### 缺陷 B｜F3-3 用「计数」代替「逐项点名」—— P1

判据原文写「三行接线齐全，缺任一条即判 FAIL」。实测：

| 样本 | update | raf | lagSmoothing | 计分 | 缺失项 |
|---|---|---|---|---|---|
| good.ts | ✓ | ✓ | ✓ | 3/3 PASS | — |
| miss-lag.ts | ✓ | ✓ | ✗ | **2/3 FAIL** | `lagSmoothing` |
| miss-update.ts | ✗ | ✓ | ✓ | **2/3 FAIL** | `ScrollTrigger.update` |
| bad.ts | ✓ | ✗ | ✓ | **2/3 FAIL** | `raf` |

两者同为「2/3 FAIL」，但**缺的东西完全不同**，而症状完全不同
（缺 `update` = 动画滞后一帧；缺 `lagSmoothing` = 低帧率下回弹卡顿）。
⇒ 判据能判红，但**不告诉人缺哪行**，Step 5 执行时会失去定位能力。
判据原文「缺任一条即判 FAIL」暗示了逐项点名，实现必须点名而非计数。

### 缺陷 C｜F2「Hero」对后台类项目是错误前提 —— P2

`supermarket-web` 是管理后台（商品/订单/看板），**天然没有 Hero 区**。
判据若机械执行「Hero = 一句主张 + 一个主 CTA」，会给后台系统开出荒谬建议。
`workflow-frontend.md` 已写「有前端面才跑」，但「有前端面」≠「有落地页形态」，
缺一层**形态判定**（落地页/官网 vs 后台/工具型 SPA）。

## 七、建议的修法（未执行，等口径）

缺陷 A 的修法有两条路，取舍不同：

1. **收窄关键词**：把 `loader|Loading|Splash` 换成页面级信号
   （`document.fonts.ready` / `window.onload` / `transition:page` / 首屏 gate 组件路径），
   代价 = 漏检自定义命名。
2. **加一步人工确认**：grep 只作**候选生成**，出建议前必须人工读命中行确认为页面级。
   代价 = 慢一步，但符合本 skill「实测 > grep 命中数」的既有纪律。

推荐 **2 + 1 组合**：grep 出候选 → 读行确认 → 只有确认过的才进建议清单。
理由：与 `workflow-s123.part2.md` 已写的「现状以实测为准，不凭 grep 计数」一致。
