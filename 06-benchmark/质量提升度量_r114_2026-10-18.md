## 0. 本轮推翻了上一轮的一个前提（先说这个）

r113 迁移方案 §4 原文：

> 本仓没有「用户任务成功率」这类外部基准；可复算的最接近口径 = 判定能力覆盖率
> ⚠️ 边界如实登记：M1 是判定面覆盖率，不是「用户任务成功率」。本仓 182 件里没有可运行的任务基准集（对手 anthropics/skills 亦无）

**这个断言不成立。** 本轮实测发现焚诀 `eval/skill_hitrate_eval_v2.py` **就是**一套可跑的任务级基准：

| 事实 | 实测 |
|---|---|
| 评测集 | `焚诀/eval/test_queries.json` —— **99 条自然语言 query**，分 5 档（easy 34 / medium 35 / hard 18 / extra_hard 5 / negative 7） |
| 标注 | 每条带 `expected_skill`（期望被命中的 skill） |
| 可跑性 | ✅ 实跑通过（managed venv，sklearn 1.9.0） |
| 指标 | Top-1 / Top-3 / 命中率 / P / R / F1 / 误触发 |
| 统计严谨性 | 自带 **Wilson 95% 抽样区间** + 「区间重叠 ⇒ 不得判提升」的可比性判定（P1-23） |
| 污染侦测 | 期望 skill 不在实时注册表的 query 判 `contaminated` 并从分母剔除（本轮 3 条） |

⇒ 有真基准就**不得**再拿覆盖率代理量冒充「质量提升」（R247 同族：代理量不得冒充观测量）。

## 1. 指标定义与口径边界

**主指标 = 混合路由 Top-1 命中率**：用户说一句话，系统把**正确的 skill** 排在第一位的比例。

| 口径 | 说明 |
|---|---|
| 测的是什么 | 路由命中——「对的东西有没有被送到手上」 |
| 不是测什么 | ⚠️ **不是**「任务做完的好坏」。它是任务质量的**上游必要条件**，不是充分条件 |
| 为什么可用 | 路由错了，后面的执行一定错；路由对了，任务才有做对的机会。这是本仓能实测到的最强代理，且**比覆盖率代理更接近任务** |
| 分母 | 99 条 query − 3 条 contaminated = **89** 条可判 |
| 区间 | Wilson 95%，若与基线区间重叠 **一律不得写「提升」** |

## 2. 基线（本轮首次登记，后续轮次与之比）

| 方法 | Top-1 | Wilson 95% | Top-3 | 命中率 | P | R | F1 | 误触发 |
|---|---|---|---|---|---|---|---|---|
| keyword（纯关键词） | 29.2% | [20.8, 39.4] n=89 | 37.1% | 56.2% | 52.0% | 40.0% | 45.2% | 0.0% n=7 |
| tfidf（纯 TF-IDF） | 25.8% | [17.9, 35.8] n=89 | 38.2% | 96.6% | 26.7% | 88.5% | 41.1% | 28.6% n=7 |
| **hybrid（混合路由 = 现役）** | **38.2%** | **[28.8, 48.6] n=89** | **50.6%** | 97.8% | 39.1% | 94.4% | 55.3% | 28.6% n=7 |

> 取值：`python 05-exec/r114_quality_ab.py --record-baseline`（基线件 `06-benchmark/quality_baseline_r114.json`）
> 复算：`cd 焚诀 && <managed venv python> eval/skill_hitrate_eval_v2.py`

**基线读数解读**（不得只挑好看的看）：

1. **现役 hybrid 的 Top-1 只有 38.2%** —— 约 6 成 query 首位是错的。这是本体系任务质量最硬的短板，且**在此前的所有对标报告里从未被量过**（一直用覆盖率/门数/技能数代替）。
2. **hybrid 的 Top-3 50.6%** —— 即使放宽到前三，仍有一半 query 找不到正确 skill。
3. **hybrid 的误触发 28.6%（2/7）** —— negative 档 7 条「本不该命中任何 skill」的 query 里，有 2 条被误触发。TF-IDF 与 hybrid 同值，keyword 为 0% ⇒ 误触发是 **TF-IDF 分支引入的**。
4. **hybrid ≈ keyword + TF-IDF 的并集**（看 `hybrid_match()` 实现）：先把 keyword 命中排前、再补 TF-IDF。这也解释了为什么 hybrid 的 Recall 高（94.4%）但 Precision 低（39.1%）——它倾向「多给几个」，用排序去兜。

### 2.1 抽样区间的正确读法

上表所有 Top-1 的 Wilson 区间**两两重叠**（keyword [20.8,39.4] / tfidf [17.9,35.8] / hybrid [28.8,48.6]）。

⇒ 按基准脚本自带的 `comparability()` 判定，三条方法的差距**全部落在抽样抖动内**，**不得**写成「hybrid 比 keyword 高 9pp」。这与 r114 基线核心结论一致：**先把量建立起来，再谈优化**。
