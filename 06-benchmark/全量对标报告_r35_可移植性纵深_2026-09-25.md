⇒ 清掉即把一个能跑的技能改成不能跑。**"未逐条看就下分类结论"正是本仓反复登记的病灶形态**（r29 推翻两条、r31 推翻落后项 #6、r32 推翻 M-1、r33 推翻 M-1′ 前置…这是第五次）。

### 1.1 于是把"该不该清"做成可机检判据，而不是继续靠语感

`05-exec/r35_username_context_audit.py`，四分类，**判据是客观事实而非观感**：

| 类 | 判据 | 处置 |
|---|---|---|
| **LOAD_BEARING** | 路径 `os.path.exists()` 为真 **或** 行内含执行语境（`--message-file`/`python `/`cd `/`.py`/`.ps1`/`path:`/`Read →`） | **禁动** |
| **ILLUSTRATIVE** | 路径在盘上不存在 **且** 行内无执行语境 | 可清（唯一一类进队列） |
| **UNKNOWN** | 取不到路径边界 | 单列，**禁就近归类**（防造出"可清量"） |
| **NON_PATH** | 命中嵌在更长 token 里（如邮箱前缀 `3753318894@qq.com`） | 单列，不混入泄漏计数 |

实测 94 处 = **LOAD_BEARING 77 · ILLUSTRATIVE 8 · UNKNOWN 8 · NON_PATH 1**
⇒ 该清的只有 **8 处 / 6 个文件**，不是 25 个文件。整改动作全部经 `rule_editor --file` 白名单落盘（受管根 `feat(skills)` 提交，逐处先 `--dry-run` 校锚点命中数，任一处失败即停不做半改），**ILLUSTRATIVE 现归零**，棘轮基线 25→**23**。

## 6. 事故与自纠（本轮）

1. **判据的聚合口径写错**：`totals_by_class` 写成 `Counter(k for r in rows for k, n in r["by_class"].items())`
   —— 数的是「文件×类别」**对数**而非出现次数，把 **94 处误报成 33**。这正是本仓 `audit-runner-safe-aggregate`
   点名的聚合误算形态，我自己犯在自己的新工具上。修法=按类累加 n，复跑取到 77/8/8/1（合计=94，与 total 自洽）。
2. **变异集里有两条"天然无鉴别力"的探针**：`judge()` 原为多 return 结构，
   改状态字符串的变异**行为不变**（仍从旧 return 出口）⇒ 若保留会像 r32 那样"看着全过其实没测"。
   修法不是硬凑锚点，而是把 `judge()` 重构成**单出口 + 状态唯一赋值**；同时撤掉需同时改两处才生效的 M4，
   并把"不误伤"方向改由 a4 直接断言覆盖 —— 如实分工，不硬报 5/5。
3. **夹具自身的三处缺陷**：空仓 `git commit` 必然 rc=1 被断言当失败；变异锚点未随实现重构更新；
   匹配用 `startswith` 未 `lstrip` 致缩进命中 0。全部为真红，逐条修后 10/10。
4. **两次字符串手术写崩补丁脚本**（转义/反斜杠），AST 前置校验**每次都拦住未落盘** ——
   这是 r34 §5.1 事故的防线在起作用的实证；此后固定「文本用 `r'''…'''`、落盘前 `ast.parse`、改文件优先 Edit」。
5. 报告与命令里引用的每个路径本轮均已实测存在（`r35_username_context_audit.py` / `r35_tracked_empty*.py` / 三份 JSON 产物），
   避免 R240 型死引用。
