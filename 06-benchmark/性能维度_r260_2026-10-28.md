## 8. 跨进程可复现性（本维必须写清的边界）⚠️部分实测

本轮在同一台机器上连跑三次全量（run A 14:31、run B 14:36 在册产物、run C 14:41 落 `_temp/r260_perfface_rerun.json`），同一份测量器、同一份名册：
run C 的结构面读数与 A/B 逐字相同（`rows=77 measured=26 no_trigger=51 self_hit=21`），`warmup_ms` 第三次又变（2497.39）——即本节结论不是两次的偶然。

| 面 | run A | run B（在册产物） | 判读 |
|---|---|---|---|
| 结构：行数 / 可测 / NO_TRIGGER / 直连件数 / self_hit | 77 / 26 / 51 / 7 / 21 | 77 / 26 / 51 / 7 / 21 | **完全一致 ⇒ 结构面可复现** |
| 5 件召回失败名单 | 同 5 件（`A-project-handoff`、`cross-platform-agent-sync`、`static-site-batch-audit-fix`、`agent-browser`、`discover-agent-cli`） | 同 | **一致 ⇒ P4 是真值读数** |
| 直连档 min/max | 0.045–0.124 ms | 0.050–0.145 ms | 同量级，稳 |
| BGE 档中位 / p75 / max | 9.723 / 14.600 / 36.648 ms | 2.446 / 2.998 / 23.496 ms | **漂移 ~3–5× ⇒ 数值面不可跨进程复现** |
| 相关性（bytes↔ms Pearson / Spearman） | −0.2112 / −0.2219 | −0.2131 / −0.3757 | 方向一致（负），量级漂 ⇒ 只可引用方向 |
| `warmup_ms` | 2152.5 | 1864.85 | 冷启动本身也在漂 |

归因假设（未插桩，故只列不判）：漂移集中在 BGE 档、直连档不动 ⇒ 与 onnx/tfidf 索引首建 + OS 文件缓存预热一致，
即**每个新进程的头几题要替全进程付索引加载**。实测旁证（同轮取证）：`06-benchmark/性能维度_r260` 的 run C 正在跑时，
焚诀 `eval/route_trace.jsonl` 同期出现**非本会话**的条目（`src=regression`，query 如「用 ffmpeg 转换音频格式」，时间戳 14:39:20/14:39:32/14:39:49，
与本会话 run C 完全重叠）⇒ **本机有并发会话在同时调同一个 router、抢同一份 CPU**，这足以解释「结构面稳、毫秒面漂」。
（顺带自证：本会话自己的 query 一条都没进 trace，`FENJUE_ROUTE_TRACE=0` 确实生效。）✅已实测

可执行结论（下游打分必须照此用）：
① 毫秒读数只在「同一次运行内」可比，跨运行只能比**层档归属与结构面**（行数/可测/NO_TRIGGER/直连件数/召回名单，本轮三次全等）；
② 要可比的绝对毫秒，需要 `--reps` 提到 9 以上、丢弃每进程前 N 题，并另开会话窗（无并发）再测——本轮未做（属口径变更，不自作主张改在册产物）；
③ `route_ms_all` 三次原始值逐件在册（77/77 行都是 3 次），任何人都能重算或换统计量。❌未实测：`--reps 9` 的收敛值。

## 9. 本件没做什么（避免被当成做了什么）

- ❌未实测：**单件端到端执行耗时**（真加载一个 skill 并跑完它的流程）。本件测的是「该件被路由唤起」这一段，
  不是「该件干活」那一段。后者要真实任务语料 + 端到端执行，不在本派工范围。
