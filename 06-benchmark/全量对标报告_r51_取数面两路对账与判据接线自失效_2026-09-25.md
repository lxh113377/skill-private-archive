## 2. 逐项差距说明

**D-84（P0）：我方引用的对手积压数取自错面，虚高 1.5–3.5 倍。**
r38/r49 报告与证据件里的 `open_issues` = 287 / 401 / 1290 / 118 / 25，来源是 REST `open_issues_count` —— **该字段含 PR**。用第二途径重测（`search/issues?q=repo:X+type:issue+state:open`）得纯 issue 面 = **134 / 143 / 368 / 58 / 17**。
同一次复核里，五个"最老 open 日期"**逐条精确复现**（含 pre-commit 那条 2018-07-02）。
⇒ 结论：**同一份证据件内，计数列错、日期列对**。所以"逐件加取值命令"不够，必须**逐条** —— 这正是 W-28 判据的形状。
（r38 的方向性结论不受影响：spec-kit 仍是唯一有到期治理的一家，`stale.yml` 是它仓库自有件。）

**D-85（P0）：新判据在真实接线下静默失效，夹具却全绿。**
我把 W-28 的豁免分叉点写成 `cut = arg if isinstance(arg, str) else 默认`，而派发处是 `fn(doc, name)` —— 传的 `arg` 是**不变式名字符串**。于是 `"2026-09-25T…" < "opponent_claims_have_retrieval"` 恒真 ⇒ **所有证据件被字典序全部豁免**，判据等于没写；而我的夹具传的是 `True`，走默认分支，16 例照样全绿。
⇒ 修法 + 立 **X-28**：可配参数必须显式校验形态（正则匹配 ISO 时间戳才当分叉点），并新增 r11/r12 **按派发处真实传法**的接线反例。这也是"直跑绿不算证据、要在真实提交上下文里跑"的同族第 N 次实证。

**D-86（P0）：`opponents` 之外的键名可绕过判据；陈旧 glob 让 r40 起的证据件长期不在受检面内。**
① 判据若只读 `doc["opponents"]`，把同类数字放进 `repos` / `peers` 即可隐身（与"文档引用违禁词=规则本体"的豁免滥用同族）⇒ 改为**按结构识别**：任何顶层列表里带 `repo` 字段的 dict 都算（反例 r14 锁死）。
② 契约 pattern 写的是 `debt_aging_r3*.json` —— 轮次过了 r39 之后新证据件**全部落在受检面外**，而"pattern 零命中判红"抓不到它（它仍命中 r30–r39 十份）⇒ 改 `debt_aging_r*.json`。这是 X-24（面内自洽≠全面）在**契约自身 pattern 面**上的第三次实证。
③ 顺带：我 r50 手写的取证件实为**非法 JSON**（相邻字符串拼接是 Python 语法），而该类件当时没有任何 pattern ⇒ 坏了无人报。已重建并纳入 `opponents_*_r*.json`。

**D-87（P1）：候选数的笛卡尔积膨胀。**
扩面后 21 组互斥候选，实际只对应 **9 个不同共用词**（"下一步建议"一个词占 6 组 = 必须侧 3 行 × 禁止侧 2 行）。⇒ 立 **X-27**：引用候选数必须同时给去重维度口径，否则一次规则分卷复制就能把严重度放大三倍。

**D-88（P1）：W-19 挂了 5 轮，收口方式是"自用一次"。**
本轮我回写 06 的归因校正注时改用写入器 `--mode note`（同一锚点入口、逐行保留行尾、同行读回验证、歧义/0 命中/幂等三态拒写，夹具 t11–t14），不再是手写补丁脚本 —— 该 [BUG] 条目本身现在也带上了这条自证注。
