## 2. 核心一：缺口量化 —— 3 个 hook 全部无 exit 1

| hook | 大小 | 含 `exit 1` | 说明 |
|---|---|---|---|
| `post-checkout` | 10 B | 否 | 占位 |
| `post-commit` | 324 B | 否 | 提交即自动 push，失败静默 |
| `pre-commit` | 1805 B | 否 | r130 装，**显式 `exit 0`** |

> **r130 当时不阻断的理由是正当的**：并行会话也在改同一个仓，无差别阻断 = 把我的判据变成「别人的活干不下去」（R269 反面）。
> **缺口不是「不阻断」本身，而是「不阻断 + 没有分级」** —— 结果是 5 条强制条目全部只在**报告里**被检查，无一在**提交那一刻**被检查。
> 取值：`Get-ChildItem .git/hooks -File | Where-Object { $_.Name -notlike '*.sample' }` + 逐个搜 `exit 1`。

## 4. 核心三：pre-commit 分级阻断

| 项 | 设计 |
|---|---|
| 跑哪些门 | 只跑 `r137_commit_gate_map.py` 判出的 `required_gate_ids` |
| 阻断谁 | 只阻断**这些门**的红；不连带阻断其他门（避免把无关的历史红算到本次头上） |
| 非纪律面 | `in_scope_n = 0` ⇒ 不阻断（保留 r130 的正当理由） |
| 逃生阀 | `SKIP_COMMIT_GATES=1 git commit ...`（须在提交说明里写明为何先落盘） |
| 台账 | `run_gates.py --gate <id> --no-ledger` ⇒ **不污染门禁台账**（新鲜度门读的是完整跑的台账） |

| 实测场景 | 结果 |
|---|---|
| 暂存 `05-exec/r137_commit_gate_map.py` | 判定触发 `proposal_evidence_face` ⇒ 该门通过 ⇒ **放行** |
| 造一条无支撑提案（`r999_probe_unbacked`） | 门面报「无读数支撑 1」⇒ 该门红 ⇒ **会阻断** |
| 恢复后 | 回到「完整 11 / 无读数支撑 0」 |

> 取值：`_temp/v23_redprobe.py`（造红 → 读数 → 恢复，全程有打印）。

## 8. 收尾补记

- 本轮**没有改任何判据、没有改任何路由**，做的是「给纪律装上牙齿」；
- 关键设计取舍：**不把 r130 的「一律不阻断」推翻，而是升级成分级** ——
  非纪律面仍然不挡并行会话的活（那是对的），纪律面才阻断。**分级比一刀切更准，也更安全**；
- 一条自省：本轮写 r137 工具时又踩了 JS 模板串引号坑（连续 4 次才编译通过），
  同一个坑在 r129/r130/r132 各踩过 —— **我给自己立的纪律里，恰恰缺一条「生成源码时用什么写法」**。
