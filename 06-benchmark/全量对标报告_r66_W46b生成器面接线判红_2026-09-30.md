## 2. 第二步：接线判红（含判据自身三处缺陷）

### ① 自排除假阳性（`generator_coverage_r*.json`）

- 现象：本工具自己写出的基线件被判 `DEAD_HANDLE`。
- 根因（实测）：`r58_generator_coverage.py` 原第 73-74 行 `if name == SELF: continue` 把**自己**踢出生成器语料 ⇒ 它的产物无人认领。不能简单取消该排除：本工具 docstring 里举例提到多个 pattern（`debt_aging_r%d_%s.json` 等），而它自身命中 `WRITE_RX` ⇒ 取消后会**反向冒充**成这些 pattern 的生成器。
- 修法：新增**路 D（自产物路）**——按**工具名**认领（归一化后**完全相等**，非前缀；且必须真有 `WRITE_RX` 写盘痕迹）。散文里提到别的 pattern（core 不等）不会命中。

### ② `all()` 过紧造成的假阴性（`attention_sim_raw_*.json`）

- 现象：该件有生成器却判 `DEAD_HANDLE`；工具绪 `DEAD_HANDLE=3`（r58 时该件曾被 `EXTERNAL_ROOTS` 接住）。
- 根因（实测）：r58 把外部匹配口径从 `any()` 收紧为 `all()`（为治 `noise_falsepositive_*` 撞 `noise_lint.py` 的假阳性）——**治好了假阳性，却造出假阴性**：`attention_sim_raw` 的 token 是 `{attention, sim, raw}`，而生成器 `焚诀/audit/attention_sim.py` 里没有 `raw`（该件由 `python audit/attention_sim.py --json > …` 重定向生成，`--json` 是 store_true 开关）。
- 修法：新增 `_external_match()` = **全 token 命中 或（最长 token 命中 且 命中数 ≥2）**。
  - `noise_falsepositive` → 最长词 `falsepositive` 不命中 ⇒ 仍拒（假阳性不复发）
  - `attention_sim_raw` → 最长词 `attention` 命中且命中 2 个 ⇒ 收（假阴性消除）
