## 1. 方法与判据（全部可复算，无模型、无相似度阈值）

### 1.1 为什么不用「一件一条 query」（两次实测推翻了直觉方案）

| # | 实测事实 | 后果 |
|---|---|---|
| 1 | GitHub search 的 `q` 是 **AND 语义**：`pdf manipulation cli stars:>500` 五词须同时命中 name/description | 首版 24 条查询里 **11 条 total=0**。0 命中会被读成「无替代」，而真相是**查询写坏了**（R247 同族） |
| 2 | search 配额 **30 次/分钟**、单查询上限 1000 条 | 182 条 query 既不划算也不可能覆盖长尾 |

⇒ 改**池化两段式**：

1. **建池**：14 条 topic/范围查询（`topic:agent-skills` 34,493 仓 / `topic:claude-code` 97,407 仓 / `skill.md in:path` 8,241 仓 等），每条取 stars 降序前 100 → 去重得 **716 仓候选池**。
2. **分派**：182 件按 12 族归类（族规则是正则，逐件可复算），族内再按**技能词**判相关，每件取 3–5 个候选 → 实测 **378 仓**（唯一面）逐仓取元数据 + git tree。

### 1.2 相关性判定踩过的三个坑（这一节是本轮最值钱的负面经验）

三版排序实测，每版都被下一版推翻：

| 版本 | 做法 | 实测失败形态 | 修法 |
|---|---|---|---|
| v1 | 二值 rel（撞词即 skill）+ 按五维总分排 | `A-ask-questions` 的候选是 cmux / Understand-Anything —— 因为 `ask` 撞了 `t-ask-s`、`multi-task` | 加 **ASCII 词边界** `\b`（逐分支加，不整体加） |
| v2 | 加词边界后按「相关性强度」排 | 反过来：52 星的 `all-documents-reader` 压过 32k 星的 `iOfficeAI/OfficeCLI`，只因名字撞词 | 改**分桶**：桶只判「是不是同一类东西」，桶内才比五维总分 |
| v3 | 分桶（身份词命中名 / 命中描述 / 仅 desc / 仅族级） | 仍把**通用工具仓**排在真 skill 仓前：`pdf` 首名是通用 office 工具，`agent-browser` 的真上游 `vercel-labs/agent-browser` 被挤到第三 | 引入**硬前置 `skill_md_n > 0`**：不带 SKILL.md 的仓不进 0/1 桶 |

**最终分桶定义**（`bucket_of()`，机读件每行候选都带 `rel` 与 `rel_strength` 可复算）：

| 桶 | 含义 | 排序 |
|---|---|---|
| 0 | 真 skill 仓（有 SKILL.md）且**身份词命中仓名** | 桶内按五维总分降序 |
| 1 | 真 skill 仓且身份词命中描述 | 同上 |
| 2 | 有相关性但**不是**真 skill 仓（通用工具/框架，须人判可用性） | 同上 |
| 3 | 仅族级命中（family） | 同上 |
| 4 | 无相关性（不该出现；出现即具名登记，禁静默吞） | — |

`rel_strength` 权重：身份词（来自 slug，即「这件 skill 之所以是它自己」）命中**仓名** +20 / 命中**描述** +10；desc 上下文词 +1。

### 1.3 词频过滤（r105/r111 教训的**正确用法**）

r105 词面尺与 r111 BGE 语义尺都败在「把相似度当结论」。本轮只把 df（文档频率）当**过滤器**：

- desc 来源的词若出现在 >35% 的族内仓里（`get` / `ask` / `agent` 这类）⇒ 无鉴别力，剔除；
- slug 来源的身份词放宽到 80%（即使常见也代表本件本身）；
- **被剔除的词落进产物的 `dropped_tokens`**，禁静默丢。

### 1.4 五维量化评分（需求 3 的落地口径）

每仓 0–5 分 × 5 维 = 25 分。**每维都有可复算锚点，不凭印象**（`score5()`）：

| 维度 | 锚点（全部来自 gh api 实测字段） |
|---|---|
| **fc 功能完整性** | `skill_md_n` 件数分档（0 / ≤2 / ≤10 / ≤100 / >100）；无 SKILL.md 时退化为 blob 规模 |
| **eff 运行效率** | `test_path_n`（tests/spec 目录数）与 `workflow_n`（.github/workflows 数）——「可自动化验证」代理，少人工往返 |
| **compat 兼容性** | license ≠ UNLICENSED + 非 archived + 有 SKILL.md 约定（与本地同一套 SKILL.md 形式） |
| **docs 文档完善度** | 根 README 数 + `docs/*.md` 规模（>5 / >40 两档）+ tree 可取的完整性 |
| **community 社区支持度** | stars 对数档（100 / 1k / 10k / 50k）+ 最近推送新鲜度（≥2026-07-01 计分） |

> 取值：`python -c "import json,io;d=json.load(io.open('06-benchmark/replacement_matrix_r114_2026-10-18.json',encoding='utf-8'));print(d['rows'][0]['candidates'][0]['score5'])"`
> 边界如实登记：**eff 与 community 是代理量**（无消费方真实耗时/采纳率样本）。严禁把五维总分读成「替代后质量必然更高」。

## 4. 判定纪律（防止本轮产物被误用）

| # | 纪律 | 理由 |
|---|---|---|
| D1 | **候选非空 ≠ 该换** | 本件只回答「有哪些候选」，回不回答「换哪个」由迁移方案按 §1.4 五维 + 同源关系联合裁 |
| D2 | 桶 2/3 的候选**默认不换** | 它们不是真 skill 仓或只是同族，换装等于把不同形态的东西硬套 |
| D3 | 五维总分**不得**单独作为替换依据 | eff / community 是代理量；必须与同源判定（r112 内容寻址）联合 |
| D4 | NO_OS_CANDIDATE 件**禁止**进换装队列 | 没有可换的对象；它们的改进只能走自建 |
| D5 | 每季度重跑本件 | 候选池会变（上游仓 star/维护状态/新仓涌现）——见季度巡检规范 §3 ⑤ |
