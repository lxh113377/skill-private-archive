### G-2 跨工具 SSL 栈差异我不知道（本轮一手）
- **症状**：`git push` 与 `gh api` 三连报 `TLS connect error: error:0A000126 unexpected eof`，
  我先归因成「网络挂了」。实测：TCP 443 True、`.NET SslStream` 握手 Tls13 成功、代理 CONNECT 返 200，
  但 Python `ssl`（含显式 ProxyHandler）一律 UNEXPECTED_EOF；本机 `curl.exe` 是 **Schannel** 后端，
  `--noproxy '*' --ssl-no-revoke` 直连 `api.github.com/zen` **成功**；带上 `-x 127.0.0.1:7897` 则 schannel 握手失败。
  ⇒ 真因 = **本地代理截 Python 的 TLS**，且 git 侧凭 `http.proxy` 配置也中招；绕行 = 仓内 `--local` 空代理覆盖（未动全局）。
  取值：`python ./_temp/r157_api.py`（三条腿：no-auth/direct/proxy）+ `git config --local --get http.proxy`。
- **我缺的知识**：Windows 上「哪个 SSL 栈走得通」的矩阵（schannel vs openssl vs 代理链），
  以及「凭据有效」与「通道可达」是两件事（token 一直是好的，坏的是通道）。
- **补法**：把「凡 Python 直连外部 HTTPS 判失败，先用 `curl.exe`（schannel）与 `.NET SslStream` 双路对账再定性」
  写进本仓判据取向；已落 07 的 R151-9（本轮执行掉并销账）。
- **验收**：任何「网络/凭据缺口」结论必须带三条腿读数（TCP / schannel / Python-ssl），缺一写「未取证」。
- **状态**：✅ 绕行已落地；⚠️ 双路对账判据**尚未进门表** → 登记 G-2a 待办（见 §3）。

### G-4 tar/路径与引号的工程细节反复吃成本
- **症状**（本轮 4 次）：① `os.path.join` 在 Windows 拼反斜杠去查 tar 的 POSIX 成员名 ⇒ `KeyError`；
  ② `tarfile` 未 `close()` 就 `os.remove` ⇒ `PermissionError WinError 32`；
  ③ PowerShell 5.1 把空串参数 `''` **丢弃** ⇒ `git config --local http.proxy ''` 静默无效（须 `'""'` 或走 subprocess argv）；
  ④ 我生成的 Python 片段里 `GOOD = json.dumps(...),` 尾逗号使值变 tuple ⇒ `replace() argument 2 must be str, not tuple`。
  取值：`python ./_temp/r157_g5.py`（前两条修后通过）、`python ./_temp/r157_proxy.py`（③④ 的取证件）。
- **我缺的知识**：跨语言拼接时的**坐标系一致**（tar 用 posixpath）、Windows 引号/参数的**层级展开**、
  以及「语法能过 ≠ 语义对」的尾逗号类静默形态。
- **补法**：写外部数据结构的脚本前先 `import posixpath` 并 `ast.parse` 自证（本仓排障速查 row 9 已是同类），
  参数化写盘一律走 subprocess argv 而非 shell 引号嵌套。
- **状态**：⏳ 待成文（登记 G-4a，§3）。
