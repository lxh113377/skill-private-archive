## 2. 核心一：缺口量化 —— 到底缺什么

漂移时能拿到 / 拿不到：

| 想知道的 | 现状 |
|---|---|
| 两个 sha（模板 / 实装） | 有 |
| 两个 mtime | 有 |
| **实装件是哪个模板版本装的？** | 无印记 |
| **装完之后有没有被改？** | 无安装时间戳可比 |
| **是谁/哪次改的？** | 实装件不在 git 内，**无历史可查** |

> **mtime 陷阱**：实装件 mtime 晚于模板 mtime，但**两种成因都长这样**
> （「装了旧模板」和「装后被人改」都会让实装件更新）⇒ mtime 无法归因。
> 取值：`python 05-exec/r139_hook_sync.py --json <件>` 只给 `template_sha` / `installed_sha`（无时间维度）。

## 3. 核心二：印记 + 六态归因（第 52 门）

### 3.1 印记机制

`r138_install_hooks.py` 安装时写 `.git/hooks/<name>.installed`，记录
`schema` / `hook` / `template` / `template_sha256` / `installed_at` / `note` 六项。

> 取值：`Get-Content .git/hooks/pre-commit.installed -Raw`。

### 3.2 六态归因

| 态 | 判定条件 | 含义 |
|---|---|---|
| `IN_SYNC` | `installed_sha == template_sha` | 无漂移 |
| `DRIFT_AFTER_INSTALL` | `installed_sha != stamp_sha` | 装后有人改了 `.git/hooks/` |
| `DRIFT_OLD_TEMPLATE` | `installed_sha == stamp_sha` 且 `!= template_sha` | 模板被改后没重装（装的是旧模板） |
| `NO_STAMP` | 无印记文件 | 归因不可用，须重装补印记 |
| `MISSING` / `TEMPLATE_MISSING` | 实装件 / 模板不存在 | — |

> **设计取舍**：`IN_SYNC` 优先于 `NO_STAMP` —— 无漂移就不需要归因（合理优先级）。
> 但「无印记」仍单列告警：它不影响本次判定，却意味着**下次漂移将无法归因**。
> 取值：`python 05-exec/r140_hook_trace.py --json <件>` 的 `face.by_class` + `face.no_stamp_n`。

### 3.3 反向验证（四态，按 #32 纪律）—— **当场抓出一个真 bug**

| 变体 | 期望 | 初版实际 | 修正后 |
|---|---|---|---|
| 装后改实装件 | `DRIFT_AFTER_INSTALL` | **`DRIFT_OLD_TEMPLATE`（判反）** | 对 |
| 改模板但不重装 | `DRIFT_OLD_TEMPLATE` | **`DRIFT_AFTER_INSTALL`（判反）** | 对 |
| 删印记（仍一致） | `IN_SYNC` + 无印记告警 | 同 | 对 |
| 真实状态 | `IN_SYNC` | 同 | 对 |

> **根因**：`installed == stamp` 说明实装件**就是当初装的模板** ⇒ 变的是**模板**；
> `installed != stamp` 说明实装件**不是**当初装的模板 ⇒ 变的是**实装件**。初版写反了。
> **若不先造变体复跑，这个反态会直接写进 #38 的判据** —— 这是 #32 纪律的第 N 次直接收益。
> 取值：`python ./_temp/v18_probe.py`（四个变体逐一跑，跑完即还原现场）。
