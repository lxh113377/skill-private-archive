## 3. 核心二：git 跟踪的外部锚点台账

`06-benchmark/hook_install_ledger.json`（schema `hook-install-ledger-r144-v1`）：

| 字段 | 内容 |
|---|---|
| `hook.<name>.lines` | 该 hook 历史行数 |
| `hook.<name>.last_line_hash` | 末行 line_hash |
| `hook.<name>.invoker` / `reason` | 谁、为什么装 |
| `updated_at` | 台账更新时间 |

**关键性质**：台账在 **git 版本历史**里——改它 = 留提交记录（提交者/时间可查）。
攻击者要同时伪造 git 历史，就进入另一个威胁模型（见 §5）。

> 取值：`Get-Content 06-benchmark/hook_install_ledger.json -Raw`。

## 4. 核心三：H7 对账（并入第 54 门）

| 检查 | 内容 |

## 5. 信任根的边界（诚实声明）

H7 的信任根是 **git 历史本身**。若攻击者能改写 git 历史（force-push / 重写台账提交），
锚点失效——但那需要**仓写权限 + 留 git 痕迹**，超出「改本地文件不留痕」的对抗强度。
对单机文本防篡改而言，git 台账是当前可用最强锚点。下一级（若需要）是远端只读副本。
