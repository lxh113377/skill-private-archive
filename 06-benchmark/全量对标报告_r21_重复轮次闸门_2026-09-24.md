## 3. 本轮已落地（对标 fail-closed，两侧实测）

新增 `05-exec/repeat_round_guard.py`（只读、确定性、无网络）：

| 判据输入 | 说明 |
|---|---|
| 同族提交数 | `git log --since` + `--pattern`（默认 `对标\|benchmark`）匹配 subject |
| 同日同指令 session | 读 `D:\global_memory\meta\lessons_usage.jsonl` 的 `query` 字段做空白剥离前缀匹配 ⇒ 兼detect **跨项目广播** |

| 漂移授权位 | `--drift` 须由调用方带实测数字使用（不接受空口"有新东西"） |

判定与退出码：`FRESH`/`THIN` → 0 放行；`INCREMENT`（有 drift）→ 0；**`DUPLICATE` → 1 禁止重跑全量轮**；取证失败 → **2（R247：无处可比不得判过）**。

**两层含对照实测（R238）**：

| 侧 | 命令 | 结果 |
|---|---|---|
| 生效路径 | `--query "将我的项目与GitHub…这是自动化任务"` | **DUPLICATE / exit 1**，并列出 5 轮·10,466 行·4 个跨仓 session |
| 反例对照 | `--query "帮我把超市web的商品图片压缩成webp" --pattern NoSuchFamily-xyz` | **FRESH / exit 0**（不误伤普通任务） |

> 过程中真踩一个 bug 并被反例侧暴露：`"--pretty=format:@@%h|%ad|%s" % ""` 残留 `%` 格式化 → `ValueError: unsupported format character '|'`，**两条路径都以 exit=1 崩**，若只跑生效侧会误判"拦截成功"。已修并复跑两侧通过——这就是 R238「单测掩盖接线错误」的第三次实物复现，值得单独沉淀。
