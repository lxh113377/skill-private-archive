### 1.2 三条结论（含被推翻的自家旧表述）

**① 星标与 CI 严格度不相关（Spearman ρ = −0.114，n=15）。**
星标前 4 名里 **3 个 workflow ≤ 1**（superpowers 0 / mattpocock 1 / anthropics 0），而 workflow 第 4 多的 N-E 只有 **36 ★**。
⇒ 这是 r28「结构纪律与星标无关」结论在**第二个独立维度**上的复现。任何「向高星标项目学」的隐含排序在本体系里应当作废——**按机制同构度选对手，不按星标**。

**② 推翻 `comparison.md` 落后项 #6 的依据（R241 只加校正注，原文不改）。**
常驻页写「addyosmani 三层 eval（结构/路由/行为）**在 CI**」。实物：其仓仅 1 个 workflow，`test-plugin-install.yml`，内容是 `actions/checkout` + `setup-node` + 校验插件安装与 `Validate skill content`；**未见三层 eval 的执行件**。
⇒ 真实成立的说法是「addyosmani **宣称**三层 eval」，「在 CI」属我们把对手 README 当成了实物——**这正是 r28 已经纠正过一次的方法论错误，在新维度上第二次复现**。已在 §7 登记为「引用对手宣称未验实物」的同形态复发。

**③ 唯一与我们同构的参照系，恰恰是 CI 最严的那一个。**
`workflow 数 ÷ 星标` 最高的是 N-E mycelium（36★/11）。它 11 个 workflow 里没有一个在构建发布物，全部守**规则资产本身**：模板纯度（禁把个人数据落进公开件）、PII 清洗、open-core 边界、行为级 eval、每日版本漂移心跳。
⇒ 本体系的判据数量（C1~C33 + 本仓 5 门 + 四门禁）**远高于** mycelium，但执行面只有「会话内有人记得跑」。这是我们与同构参照系之间**最刺眼的一处反向差**：判据最硬，执行最靠自觉。
