## 3. 逐项差距说明（本轮新增两条实测结论）

### 结论① rationalizations 的缺口是真的，且与 verification 相反：严格同义零假阴性
新工具 `05-exec/r30_section_robustness.py`（段参数化，四档）对同一批 166 文件实测：

| 段 | 档1 现行尺 | 档2 严格同义 | 档2b 功能等价宽写法 | 档3 仅小节标题 |
|---|---|---|---|---|
| **rationalizations** | 23 = **13.9%** | 23 = **13.9%**（差 **0**） | 118 = **71.1%**（差 +95） | 55 = 33.1% |
| verification（同器复跑） | 101 = 60.8% | 120 = 72.3%（差 +19） | 123 = 74.1% | 55 = 33.1% |

⇒ 两面镜子照出两种病：**verification 缺口的 29.2% 是没用了那组词；rationalizations 在"借口/托词/自我说服"这组严格同义词上换不出任何新命中，缺口 13.9% 就是 13.9%**。
但同一批技能里 **95 条（57.2%）确实带有"反模式/常见误区/禁忌/坑/不适用"一类的负面指引**，只是没做成 addyosmani 那种「借口 → 逐条反驳」表。
所以对外表述必须分档：**"我们缺制度级的反理性化表"成立；"我们完全没有负面指引"不成立。**

### 结论② 真队列按最保守口径取，首批 5 条已落地
"无论如何都得补"= 档2b 也全缺 ∩ 自建维护面 = **14 条**。本轮从中取工作区干净、且能写出**该技能特有失败形态**的 5 条：

| 技能 | 写进去的借口（左列）→ 反驳要点 |
|---|---|
| `story-scan` | 未分流就默认长篇 / 条目不足不标 `[数据稀疏]` / 平台模板文本不清洗 / 单平台失败中断整轮 |
| `video-breakdown-skill` | 把切分失败当"本来就是单镜头" / 打印了目录就当帧齐 / 空字段交下游不报错即完成 / 合并生效未对账 |
| `local-vram` | 打印"已更改"即报完成 / 写入当生效 / 越界反例可省 / 默认值不必查基线 |
| `code-review` | 挑几处即报"全库已审" / 行号待会儿补 / 静态读码不跑构建 / 老代码有风险就不提 |
| `utf8-encoding-fix` | 肉眼无乱码即跳过 / BOM 无所谓 / 全量按 GBK 试转 / 脚本跑完当修好 |

**零套模板**：每条反驳都指向该技能自己的失败形态（这正是要补的东西本身）。
复测：档1 23→28、档3 55→60，五条逐技能 `t1/t2/heading_only` 全翻正。
