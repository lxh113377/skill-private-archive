## 2. 四级演练读数

### L1 单文件还原 —— PASS

- 命令：先注入损坏态 `printf DRILL-CORRUPT > $F`，再 `git show HEAD~1:06-benchmark/free_tool_roster_latest.json > $F`，sha256 + `cmp -s` 双比。
- rc=0；损坏态 sha `7bf671b7…` → 还原后 sha `e3f9febf…` == `git show HEAD~1:<F>` 目标 blob `e3f9febf…`（**相等**）；`cmp -s` 逐字节 0；还原后 `git checkout -- $F` 工作树回 clean。
- **演练抓出的真坑（判据级，非还原级）**：本机 `core.autocrlf=true`，工作树 993 行 CRLF、`git show` 输出 LF。首跑拿「工作树 sha」对「HEAD blob sha」⇒ 误判 FAIL。坐实方式：`tr -d CR` 归一化后 `9afb21c2…`(WT) → `e3f9febf…` == HEAD blob ⇒ 差异 100% 由 CRLF 解释。
  正解判据 = 目标取 `git show <rev>:<F> | sha256sum`，或直接 `cmp -s <(git show <rev>:<F>) <F>`；要拿工作树比必须先归一化。**纸面 §6 的 L1 验证栏（复跑 run_gates.py 至 PASS）没写这条，是纸面预案的真缺陷。**

## 8. r260 父级复跑抓出的两处判据缺陷（Lead 补记，R241：上文原文一字未改）

按 #44 ⑧「父级独立复跑至少一条判据，不采信自述」，Lead 复跑本演练时抓到两个**比自述更红**的问题，

| # | 缺陷形态 | 为什么严重 | 修法与实测 |
|---|---|---|---|
| 1 | `l2.sh` attempt B 在 revert **之后**才取 `git show HEAD~1:$F` 当「升级前态」；revert 后 HEAD~1 恰是被撤销那笔（= 升级态），于是 PREVSTATE 与 UPGRADED 打成同值 | 断言退化成恒等式 ⇒ **无牙**（回滚失败也会报绿）。属 #48「打印 want 不看 got」同族 | revert 前先从 `HEAD^` 捕获真前态，新增承重行 `L2B_ASSERT_EQ`。实测复跑：PREVSTATE `c803c998…` ≠ UPGRADED `e3f9febf…`（两值分离）、REVERTED `c803c998…` == 真前态、`L2B_ASSERT_EQ=1` |
| 2 | `verify.sh` 的「脚本内不含 global_skills 写操作」写作 `grep -c global_skills *.sh` | 自我指涉：把这一行自身与只读 `ls`/`find` 检查都算成命中（读数 2/5 却不等于「有写」）⇒ 假红方向，会让人去找一个不存在的越界写 | 改成只匹配写形态（重定向/cp/mv/rm 进受管根、受管根内 git 写子命令）。实测复跑末行 = `0` |
